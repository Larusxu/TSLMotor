> **2026-11-02 重构阶段 B 更新：真实 byte 后端暂不可用。** 用户提供的 TMC6460 Rev.0 p.104–106 定义 12 位地址和 16 位数据，尚未说明它与 M24C02 的字节地址及字节序映射。`storage.rs` 的 probe/dump/save/load/erase 在改引脚或通信前明确拒绝；不能继续按本文历史单字节假设操作。新增 `io_rom.rs` 修复 idle→零回显→命令→完成回显的握手并通过离线测试。以下内容作为旧 TSL1 布局与迁移审计记录保留，不代表当前真实存储功能已验证；SSI 排他、恢复及新鲜反馈检查仍待接入。

> 对应界面：**板载存储**页（`src/pages/Storage.tsx`）。
> 实现：上位机 [`storage.rs`](../../src-tauri/src/storage.rs)（I²C 命令 + 参数块编解码 + A/B 双备份）。

## 〇、这颗片子是什么、接在哪

| 项 | 值 |
|---|---|
| 型号 | ST **M24C02-FMH6TG**，I²C EEPROM，**2 Kbit = 256 B**，页 16 B，写周期 ≤5 ms，>400 万次 |
| 封装 | UFDFPN5（DFN5 1.7×1.4 mm），5 个引脚：`VCC`/`VSS`/`SDA`/`SCL`/`#WC` |
| 地址 | DFN5 的 `E2/E1/E0` 读作 0 ⇒ 器件地址固定 **`0xA0`(写) / `0xA1`(读)** |
| `#WC` | 接地 = **写使能**（手册 Figure 6：WC = 0 → data write enabled），没有硬件写保护 |
| 接线 | `SDA → TMC6460 HALL_U(pin17)`、`SCL → HALL_V(pin18)`，各 4.7 kΩ 上拉到 4V5 |

**代价**：`HALL_U/HALL_V` 是芯片唯一能当 I²C 用的引脚，一旦启用，霍尔/第二路反馈就没了（`HALL_W` 已被 SPI/SSI 的 `DIRECT_OUT[2]` 占用，见 [`01-编码器.md`](./01-编码器.md) 第 10 条）。本页会在用之前自动改 `IO_MATRIX(0x006)`：`PIN_HALL_U[8:6]=3`（SDA）、`PIN_HALL_V[11:9]=3`（SCL）。

## 一、上位机怎么访问它（只用芯片自带 ROM 功能，不写固件）

| 功能 | `IO_COMMAND(0x381)` | 回读 |
|---|---|---|
| I²C 初始化（开漏） | `0xAA02yyyy`，`fI2C = 60 MHz/4/(yyyy+1)`，`0x95` → 100 kHz | `RESPONSE_0` 回显签名 |
| 写一个字节 | `0xEyyyzzzz`（`yyy` = 12 位字地址，`zzzz` = 数据） | `RESPONSE_0` 回显 |
| 读一个字节 | `0xDyyy0000` | `RESPONSE_1[7:0]` |
| 整片读进 RAM | `0xAA030000` | 之后用 `0xCyyy0000`（`RAM_READ`）逐字取 |

上位机流程（`storage.rs`）：

```
enable_i2c_pins()  →  init_i2c(100 kHz)  →  逐字节读写
写：每次 I2C_WRITE 后 sleep 6 ms（EEPROM 写周期 ≤5 ms），再核对 RESPONSE_0 回显
```

> ⚠️ **未在真板验证的部分**：`I2C_WRITE/I2C_READ` 的 `yyy` 手册只写"12 位地址"。按 24C02 的常规实现应是"器件地址固定 `0xA0/0xA1` + 低 8 位字地址"，本实现按这个假设做（`addr & 0xFF`）。若真板上回读不符，先用 `tmc6460_upper_pc/eeprom_test.py` 打一遍原始寄存器日志确认。

## 二、参数块格式（A/B 双备份 + CRC）

```
0x00 .. 0x6F  block A（112 B）
0x70 .. 0xDF  block B（112 B）
0xE0 .. 0xFD  保留
0xFE          自检字节（写读测试用，不进参数块）

block:
  [0..4)    "TSL1"
  [4]       版本 = 1
  [5]       载荷长度 = 92
  [6..8)    序号 seq（u16 LE，越大越新）
  [8..100)  23 × u32 LE（见下表）
  [100]     CRC-8（poly 0x07，覆盖 [0..100)）
  [101..112) 0xFF
```

| # | 字段 | 说明 | # | 字段 | 说明 |
|---|---|---|---|---|---|
| 0 | `cpr` | 编码器步数 | 12 | `vel_i` | 速度环 I |
| 1 | `poles` | 极对数 | 13 | `pos_p` | 位置环 P |
| 2 | `csa_gain` | `0x0C3` | 14 | `pos_i` | 位置环 I |
| 3 | `pwm_max_count` | `0x103` | 15 | `flags` | bit0 = 电角度已标定 |
| 4 | `phi_e_offset` | `0x242` | 16 | `motor_id` | 电机编号 |
| 5 | `torque_limit_ma` | 力矩限幅 | 17 | `axis_origin` | 原点 counts |
| 6 | `flux_limit_ma` | 磁链限幅 | 18 | `axis_min` | 软限位下限 |
| 7 | `vel_limit_rpm` | 速度限幅 | 19 | `axis_max` | 软限位上限 |
| 8 | `uq_ud_limit` | `0x149` | 20 | `lead_um` | 丝杆导程 µm |
| 9 | `cur_p` | 电流环 P | 21 | `counts_per_rpm_x10` | 305.4 → 3054 |
| 10 | `cur_i` | 电流环 I | 22 | `ma_per_count_ua` | 0.20131 mA → 201 |
| 11 | `vel_p` | 速度环 P | | | |

**为什么两份**：`#WC` 接地、没有硬件写保护，写一半掉电就可能毁掉一份。保存时先写 A、回读校验通过才写 B；读取时取「CRC 通过且 seq 更大」的那份。作废只是把两块的 magic 清成 `0xFF`（8 字节写，不用擦 224 字节）。

## 三、界面怎么用

1. **自检**：`HALL_U/V` 改 SDA/SCL → `I2C_INIT_OD` → 在 `0xFE` 写 `0xA5`/`0x5A` 并回读 → 恢复原值。结果卡会显示 IO_MATRIX 改动前后的值、I²C 时钟、写读对照。
2. **读取全部 256 B**：十六进制视图，青色=块 A、绿色=块 B、黄色=自检字节。
3. **参数块表单**：点「从界面常量取值」把当前 `CPR / 极对数 / CSA / PWM / 换算系数` 带进来，其余手填；**勾选确认** 后「保存到 EEPROM」。
4. **从 EEPROM 读取**：读出后自动填回表单，并显示 `A:✓ B:✓`、序号、取自哪一块。
5. **应用到界面常量 / 写入 0x242**：把读到的值送进界面状态或直接写进芯片寄存器（写入前需 ARM 无关，但要求已连接）。
6. **作废参数块**：清 magic，测试"未标定"分支。

耗时参考：一次保存 ≈ **5 s**（224 次单字节写 + 224 次回读，每次 6 ms 写延迟 + UART 往返），界面会显示实测 `elapsed_ms`。

|---|---|
| `0xAA01/0xAA02` | 记录 I²C 时钟，`RESPONSE_0` 回显 |

## 五、还没做 / 注意

- **上电自动加载**：仍要人点「从 EEPROM 读取」再写寄存器。真正自动加载要么写进 TSLHand 主控固件（开机读 EEPROM → 写 0x240/0x242/0x250/0x0C3/0x103/0x140…），要么用芯片的 `I2C_EEPROM` + `RAM_EXE`，后者需要应用笔记里的 RAM 代码格式，目前没做。
- **写入期间桥臂必须是 `PWM_OFF`**：`storage::save()` 会先写 `MOTOR_MOTION = PWM_OFF`；因为 IO_MATRIX 一旦改动，引脚功能立刻就变了。
- **EEPROM 与霍尔互斥**：启用后不能再接霍尔/第二路 ABN，做双反馈冗余的设计要重新考虑。
- **真板首测顺序**：自检 → 读全部 → 保存 → 断电重启 → 读取，确认 `seq` 递增且 CRC 通过。
