# 对齐与闭环（PHI_E ALIGNMENT / CLOSED LOOP）策略说明

> 对应界面：**对齐与闭环**页（`src/pages/Align.tsx`）。
> 实现：对齐 [`calibrate_phi_e`](../../src-tauri/src/procs.rs:586)、拟合 [`fit_offset`](../../src-tauri/src/procs.rs:772) / [`phi_e_offset_from`](../../src-tauri/src/procs.rs:871)、

> 手册依据：TMC6460 p.69–70「Phi E Calculation / Phi E Alignment」、p.180–181（`0x240`/`0x242`/`0x250`）。

## 〇、目的：找出「编码器角度 ↔ 转子电角度」的零点差

编码器只测**机械角**，FOC 需要**电角度**。芯片内部链路是：

```
PHI_EXT_A(0x24D)  ──16 位换算──▶  A16 = raw × (CPR_INV >> 8) = raw × 65536/CPR
                                  │ 14 bit + CPR=16384 → ×4
                                  ▼
                     A16 × PHI_E_MUL_FACTOR(0x250[7:0] = 极对数)
                                  +
                     PHI_E_OFFSET(0x242[15:0])
                                  ▼
                            FEEDBACK.PHI_E(0x251) ──▶ FOC 换相
```

`PHI_E_OFFSET` 就是这条链上唯一的自由量：**把它调对，转子磁场方向才和电流矢量方向重合**。调错的后果不是"精度差一点"，而是换相偏 → 力矩缩水、抖动、发热，偏 180° 时直接堵转/飞车。

> ⚠️ 所以：**新电机 / 换了磁铁 / 拆过联轴器，必须重跑对齐**；只有复现同一台已验证的板子才可以用遗留表里的已知偏移。

## 一、我们现在的对齐策略（开环四点扫描 + 线性拟合 + 圆周平均求偏置）

界面默认参数：对齐电流 **300 mA**、稳定 **700 ms**、步进 **90°e**、扫描上限 **720°e**、自动写回 `0x242` 勾选。

### 1. 基础配置（不动转子）

| 动作 | 寄存器 | 值 |
|---|---|---|
| CSA 增益 | `0x0C3` | 3（4×，0.20131 mA/LSB） |
| 电流环 PI | `0x142` / `0x143` | `(64<<16) | 48` |
| 力矩/磁链限幅 | `0x14A` | `(8192<<16) | 8192`（counts，×4 档满量程的一半以上，保证对齐电流能到位） |

### 2. 使能驱动

`0x101` 读-改-写，置 `bit31`（电荷泵）+ `bit16`（`DRV_EN`）。

### 3. 进入「开环电角度 + 力矩」模式（这是关键）

```rust
motor_motion_openloop(MODE_TORQUE, poles)   // 0x100 = (1<<15) | (3<<7) | poles
                ↑ RAMP_USE_PHI_E = 1
```

- `MOTOR_MOTION.MODE = TORQUE`：只跑力矩环，**不用反馈角度**；
- `RAMP_USE_PHI_E = 1`：换相用的 `phi_e` 由**内部斜坡发生器**产生，而不是编码器；
- 斜坡参数：`RAMPER_V_MAX=0x10000`、`V_START=0`、`A1=0x20000`、`A_MAX=0x40000`。

于是转子被"电流矢量"牵着走，走到哪儿是**我们自己规定的**——这才让"编码器读数 vs 已知电角度"的对照成立。

### 4. 施加对齐电流（d 轴锁住转子）

`0x14E`（`TORQUE_FLUX_TARGET`）写 `flux_ma / ma_per_count`（300 mA ≈ **1490 counts**），等 300 ms，回读 `0x153` 确认实际值。

> 300 mA 是**项目经验值**：Tesla 手指电机限幅只有 800 mA，厂商默认的 10000 counts ≈ 2 A 会把电机烧热。电流越大对齐越准，但发热与风险同步上升。

### 5. 双向扫描：0° → 720°，再 720° → 0°

每个定位点：

1. `0x152`（`POSITION_TARGET`）写 `(deg % 360)/360 × 65536`——注意**目标角是 16 位电角度**；
2. 轮询 `0x1C3`（`RAMPER.PHI_E`，内部开环角），与目标差 < `0x800`（约 2.8°e）就算到点，超时 2.5 s；
3. 再等 `settle_ms`（700 ms）让机械振动停下来；
4. 读 `0x24D`（`PHI_EXT_A`）按帧长度取掩码 → **原始编码器值** `enc`（14 bit 下 0…16383）。

**为什么扫 720°**：电机是 1 对极时，机械角 = 电角度，扫两圈才能让**同一电角度**在正、反两个方向各出现一次，抵消齿槽/摩擦造成的单向误差。
**为什么反向再扫一遍**：磁滞与静摩擦会让"正转到 90°"和"反转到 90°"差几个 count；同一角度的多次采样取平均后再拟合。

### 6. 拟合（两个独立结果，用途不同）

**① 线性拟合（质量指标）**

把 `deg % 360` 相同的点分组取平均 → 按 ±8192 解缠绕（跨 16384 回绕）→ 最小二乘 `enc = k·deg + b`，给出 **R²**、截距 `b`（0° 时的编码器值）、斜率 `k`（理论值 16384/360 ≈ 45.51 LSB/°）。

**② 偏移（真正写进芯片的量）**

按手册 p.70 的"平均差值"法，对**每个采样点**算一次差值再取圆周平均：

```
target16 = (deg % 360)/360 × 65536
converted = enc × (65536 / CPR) × 极对数          ← 14 bit/CPR=16384 时即 enc × 4 × poles
diff      = (target16 − converted) mod 65536
OFFSET    = 圆周平均(diff)                        → 写 0x242
```

> 这一条是 **1.0 版修正过的**：早先的实现写成 `OFFSET = −b`（直接用 14 位原始 count），漏了 `×4 × 极对数` 这一层，会让偏置小 4 倍（1 对极、b=1000 时该写 `0xF060`，却写成 `0xFC18`），闭环必然换相错乱。现在有单测锁住：`offset_uses_16bit_scaling_not_raw_counts` / `offset_zero_when_already_aligned` / `offset_respects_pole_pairs`。

### 7. 门限与写回

| 条件 | 行为 |
|---|---|
| `R² > 0.9` 且勾了「自动写回」 | 写 `0x242`（低 16 位）并回读校验 |
| `R² ≤ 0.9` | **不写**，日志提示"拟合质量不足" |
| 勾了「干跑」 | 只做基础配置 + 施加电流，不扫描不写回 |

判定标准：**R² > 0.99 才算过**；0.9–0.99 可以先用，但要查打滑/极对数/SPI 掩码。

### 8. 释放

`0x14E = 0` → `MOTOR_MOTION = PWM_OFF`。对齐结束时桥臂是关的，电机不发力。

## 二、闭环策略（速度环）

### 0. 这个卡片是干什么的：整条链路的"通电验收"

**它不是生产控制，是调试用的最小可运行验证。** 前面所有步骤（SSI 时序、`CPR_INV`、`0x242` 偏移、PID、限幅、测速配置）都是"参数"，只有让电机动起来才能知道它们**凑在一起对不对**。速度环就是那条最安全的验证路径：

```
目标转速 → 误差 → 速度环PI → 力矩电流 → FOC（用 PHI_E 换相）→ PWM → 转子
             ▲                                                  │
             └──────── 实际转速（编码器 → PHI_EXT_A → PHI_E）◄───┘
```

**"闭环"的含义**：转子被转了多少由编码器测出来、反馈回去修正，控制器只负责"把误差压到 0"；一旦反馈错了（偏移错、方向反、极对数错），闭环就会**主动把错误放大**（抖动、飞车），这也正是它能当"验错工具"的原因——错得越厉害，现象越明显。

**它一次能验证六件事**：

| 验证项 | 通过的表现 | 不通过的表现 |
|---|---|---|
| `0x242` 电角度偏移对不对 | 小电流就能平稳转、力矩足 | 抖动 / 声音大 / 一转就飞车 |
| 编码器方向 | 正 RPM → 正转 | 指令正转、实际反转（需在编码器页处理方向） |
| 极对数 `PHI_E_MUL_FACTOR` | 转速跟得住、无周期性顿挫 | 每圈周期性抖动（电角度每圈多/少转了几次） |
| 测速配置（`0x244/0x245`、周期测速） | `0x154` 读数稳定、接近目标 | `0x154` 乱跳或恒为 0 |
| PID 与限幅是否匹配电机 | 阶跃无大超调、稳态误差小 | 摆动 / 振荡 / 顶到限幅仍不达标 |
| `0x0C3` 与 mA/LSB 换算 | 力矩限幅值符合预期 | 电流读数与实际不符（差 4 倍） |

> 手册也是这个顺序：p.70 说对齐完成后 *"the resulting angle can now be used for **closed-loop operation**"*——闭环是验证对齐的手段，不是另一件事。

**为什么先验速度环、而不是位置环或力矩环**：

- 速度环**对负载不敏感**（外加重物也只是电流变大），且自带"斜坡→稳态"的天然可比性；
- 位置环需要软限位/行程保护才安全（那是「机械行程」页的事），且更容易因原点/导程配错而撞机；
- 力矩环没有"目标 vs 实际"这种一眼能判的指标。

因此流程是：**编码器页（把尺子定好）→ 对齐页（把零点对齐）→ 速度闭环（跑起来验收）→ PID 页（整定）→ 行程页（加保护）**。真正的手指/关节控制在生产固件里走位置模式，不经过这个卡片。

### 1. 启动

```rust
MOTOR_MOTION = MODE_VELOCITY + poles     // 0x100，RAMP_USE_PHI_E = 0 → 用编码器反馈
GDRV |= (1<<31) | (1<<16)                // 使能驱动
0x150 = round(rpm × 305.4)               // 目标转速内部单位
```

- **305.4 counts/RPM**：由 `CPR 16384 × CPR_INV 1024 = 2^24` 与 `f_SYS 60 MHz` 推出，与遗留上位机一致；
- 只写目标值，**不碰 PID 与限幅**——那些由「PID 与限幅」页负责（`0x140`~`0x14D`）；对齐页只在你按下"启动闭环"时才下发速度目标。

### 2. 停止（急停同一条路径）

```
0x150 = 0  →  0x14E = 0  →  等 200 ms  →  MOTOR_MOTION = PWM_OFF  →  清速度积分器 0x15F
```

先给 0 目标再关桥，避免"突然断流"造成的机械冲击；最后清积分器，防止下次启动带着旧积分起飞。

### 3. 闭环前必须成立的四条（界面右下「闭环前检查」）

1. **编码器随手转变化**（`PHI_EXT_A` 不是常数 0）；
2. `0x0C3 = 3`（4×）——否则量程与分辨率都不是预期；
3. PID 已写入，且**电流归一化 = Shift by 8**；
4. `0x14A` 力矩限幅 > 0。

### 4. 已知现象与处置

- **300 RPM 目标下实际在 200–330 摆动**：速度环 P/I 偏大或测速更新率不足 → 去「PID 与限幅」做阶跃重新整定；
- **一转就飞车 / 声音突变**：立刻急停，优先怀疑 `0x242` 偏移（用错了别人的值）、编码器方向反、`0x14A` 限幅过大；
- **转速上不去但电流已顶到限幅**：`0x0C3` 档位、`maPerCount` 与限幅换算不一致（差 4 倍的经典坑）。

---

## 三、一句话总结策略

> **开环把转子摆到已知电角度 → 读编码器 → 线性拟合看质量（R²）、按手册的"平均差值"算偏置（含 ×4 与极对数）→ 只在高 R² 时写回 0x242 → 再切到速度闭环，用 PWM_OFF 作为唯一的安全出口。**
