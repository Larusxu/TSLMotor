# 编码器参数（MT6701 · SSI 14-bit）逐值说明

> 对应界面：**编码器**页 → 卡片「编码器参数 / MT6701 · SSI」。
> 本文解释的截图值 = 预设 `MT6701 · SSI 14-bit - ENC_N` 的默认值，且处于「新电机第一次上电」状态（未写 `0x242`）。
> 实现：页面 [`Encoder.tsx`](../../src/pages/Encoder.tsx)、预设与遗留表 [`presets.ts`](../../src/lib/presets.ts)、真正落盘的 12 步 [`setup_encoder`](../../src-tauri/src/procs.rs:178)；同一组常量的遗留固件版本见 [`motor_config.h`](../../../Tesla_hand_temp_176/applications/motor_config.h:29)。

**一句话结论**：这一页是把「MT6701 的 SSI 时序 + TMC6460 的反馈链路标尺」一次性写进 **TMC6460**——引脚复用与 IO 控制器（谁来产生 SPI 时钟）、反馈通道 A 的标尺（CPR/CPR_INV）、反馈输出（极对数）、执行器与采样参数（PWM 周期、CSA 增益）；**编码器侧没有任何写入**。

## 〇、目的：这一页配的是 TMC6460，不是编码器

**这一页的每一个数值都写进 TMC6460**（上位机经 UART 写它的寄存器）。MT6701 是**纯 SSI 从机、没有任何可写寄存器**——TMC6460 的 IO 控制器只是给它打 SCK，把返回的 14 位角度收进自己的 `PHI_EXT_A(0x24D)`。所以整页没有"写进编码器"的数据；连「发送数据 `RESPONSE_1`」也只是 TMC6460 侧准备的 MOSI 载荷（MT6701 不需要命令字，实际发 0）。

换句话说：**本页 = 教 TMC6460「怎么读编码器」+「怎么把读到的角度换算成电角度」+「顺手设好执行器时基」**，编码器本身一个字节都不改。

| 组别 | 字段 | 数据最终写进 | 地址 / 位域 |
|---|---|---|---|
| 角度标尺 | 编码器步数 CPR | TMC6460 | `0x240` = `SRC_SEL_A[27:24]` + `CPR_INV[23:0]` |
| 角度标尺 | 极对数 | TMC6460 | `0x250[7:0]`（+ bit22 测速源） |
| 角度标尺 | 电角度偏置 | TMC6460（本步**跳过**） | `0x242[15:0]` |
| SPI 时序 | 帧长度 / SPI 模式 / SCK / CSN 高电平 | TMC6460 | `IO_COMMAND(0x381)` 的 `u[4:0]` / `[27:26]` / `[7:0]` / `[23:16]` |
| 引脚复用 | 片选接在 ENC_N | TMC6460 | `IO_MATRIX(0x006)` + `IO_COMMAND` 的 `u[7]` |
| 数据搬运 | 数据掩码 / 发送数据 | TMC6460 | `0x384` / `0x383` |
| 执行器与采样 | PWM MAX_COUNT / CSA 增益 | TMC6460 | `0x103[15:0]` / `0x0C3[1:0]` |
| 面板 | 编码器预设 / 板上存储 | **不写任何芯片** | 只填界面 |
| 编码器侧 | MT6701 | **没有任何写入**，只被读 | — |

## 术语：LSB / MSB / 位 / 量程 是什么

后面几条会反复用到「LSB」，这里先统一说清楚。

**LSB = Least Significant Bit（最低有效位），MSB = Most Significant Bit（最高有效位）。** 一个 N 位二进制数里：

```
bit13 bit12 … bit1  bit0
 ↑MSB                  ↑LSB        权重分别是 8192 … 2 … 1（14 位时）
```

- **MSB** 是最左边那位（权重 2^(N−1)），**LSB** 是最右边那位（权重 1）。整个数 = 各位 × 各自权重 之和。
- 例：`0b10_1010_1100_0101` 这个 14 位数，最左的 1 权重 8192，最右的 1 权重 1。

**但工程上更常用的是第二个意思：「1 个 LSB」= 数字量变化 1 所代表的物理量 = 分辨率。** 所以卡片上那些 "mA/LSB"、"°/LSB" 读作"**每 1 个计数代表多少**"：

| 说法 | 含义 | 本页/本机对应 |
|---|---|---|
| 1 LSB（位） | 二进制最低位，权重 1 | 掩码 `0x00003FFF` 就是"只留低 14 位"，把高位丢掉 |
| 1 LSB（量） | 计数 +1 对应的物理量 = **分辨率** | 电流 `0.20131 mA/LSB`；角度 `0.02197°/LSB`（14 位原始）、`0.0055°/LSB`（缩放成 16 位后） |
| MSB 先出 | 先发权重最大的位 | MT6701 SSI 帧 MSB 先出，所以只打前 14 个 SCK 周期就能拿全角度 |
| N 位 / N bit | 该量用 N 个二进制位表示，共 2^N 个档 | 14 bit → 16384 档/圈 |

**一个等式记住它们的关系**：

```
量程 = 档数 × 1 个 LSB        档数 = 2^N（有符号数时，正向量程只占一半）
角度：16384 × 0.02197° = 360.0°                     ✔
电流：32768 × 0.20131 mA ≈ 6.60 A（= 1× 档 ADC 上限）       ✔
```

**这件事的准确说法**：CSA 增益**不改变 1 个 LSB 代表的电流**（Table 20 里没有增益这一项），它改变的是**能数到多少个 LSB**（裁切点 `2¹⁵/增益`）。所以"量程 ↔ 分辨率"的权衡在这里体现为"量程 ↔ 可数的位数"，1 LSB 本身是固定的 0.20131 mA——详见第 12 条。

## 一、SSI 是什么（这一页为什么要配"时序"）

**一句话**：SSI（Synchronous Serial Interface）是编码器最常用的**单向同步串行**绝对位置接口——**主机出时钟，从机按位移出整圈绝对角度**；没有地址、没有命令、没有写操作。

**和 SPI 的关系**：电气与时序上就是"只用「主机→从机」方向的 SPI"。通用 SSI 规范常用 RS-422 差分长线传输，而这块板是 **3 线单端**（`SCK / SDO / CSN`；页面报警文案也写「检查 SCK/SDO/CSN 接线」）。所以 TMC6460 里那个叫 `SPI_ENC` 的功能块，配的就是 SSI：**SPI 的时序参数 = SSI 的时序参数**。

**三根线各干什么**：

| 信号 | 方向 | 作用 | 本页对应的值 |
|---|---|---|---|
| `SCK` | TMC6460 → MT6701 | **时钟**。每个上升沿编码器换下一位、每个下降沿主机采样；占空比 50%，空闲为低（CPOL=0）。没有时钟，编码器一位都不出 | `SCK 频率 = 2 MHz`（half=14）、`SPI 模式 1` |
| `SDO` | MT6701 → TMC6460 | **数据**。帧内 MSB 先出 24 位（角度 14 + 状态 4 + CRC 6）。**只出不进**，编码器没有接收脚 | `帧长度 14 bit`、`数据掩码`、回读的 `PHI_EXT_A` |
| `CSN` | TMC6460 → MT6701 | **片选 / 帧同步**。**拉低 = 一帧开始，拉高 = 一帧结束**：低电平期间 SDO 才有效，高电平期间编码器复位移位寄存器、准备下一帧 | `CSN 高电平 16`、预设名后缀 `- ENC_N`（即 `u[7]=1`）决定 CSN/SDO 在 `DIRECT_OUT[1]`/`[2]` 之间怎么分配（本板即 ENC_N ↔ HALL_W 对调） |

要点：SSI **没有第 4 根 MOSI**——所以「发送数据 `RESPONSE_1`」在本板是空操作；TMC6460 侧那几个引脚（含用不到的 SDI）只是由 `IO_MATRIX(0x006)` 整组切到 IO 控制器，多余的那根不接线。

接线排查顺序（三根断线表现不同）：`PHI_EXT_A` **恒为 0** → 多为 `SCK` 或 `CSN` 没到（没有帧），或 `SDO` 被拉低；**读数乱跳/角度不连续** → 多为 `CSN` 帧边界没建立或 `SCK/SDO` 干扰；**值跳一位、整体偏** → 先怀疑 `SPI 模式`。三根线都正常但一直 0，再查 `u[7]` 与预设是否匹配。

**读一次数的完整过程**（MT6701 + TMC6460）：

1. TMC6460 拉低 CSn（本板走 `ENC_N`）；
2. 打 24 个 SCK（全帧；本页 14 bit 预设**只打前 14 个**）：**编码器在上升沿更新下一位，主机在下降沿采样** → CPOL=0 / CPHA=1 = **模式 1**；
3. 数据 MSB 先出，24 个 SCK 周期（24 位）依次是：

   ```
   bit  23 ……… 10 │ 9 … 6 │ 5 … 0
        D[13:0]   │ Mg[3:0]│ CRC-6
        角度 14 位 │ 状态 4 位│ 校验 6 位
   ```

   ```
   CSn  ‾‾\___________________________________________/‾‾‾‾‾
   SCK  _____/‾\_/‾\_/‾\_ … _/‾\______________________
               ↑上升沿：编码器换下一位
               ↓下降沿：TMC6460 采样        = 模式 1
   SDO  XXXXX=D13=D12= … =D0=Mg3…Mg0=CRC5…CRC0=XXXXXX
        前 14 位＝角度  4 位    6 位
   ```

4. TMC6460 拉高 CSn，等 `tSPI_CSH`（手册：与 `SPI_CSH_CNT` 的平方成正比、最短 6 µs）后再读下一帧。

**SSI 的几个性质，正好解释了本页那些值**：

| SSI 性质 | 在本页对应的值 |
|---|---|
| 每帧都是**完整绝对角度**，不累积、不丢步 | `PHI_EXT_A(0x24D)` 直接就是角度；不需要回零/索引 |
| **MSB 先出** → 截断即取高位 | 只打 14 个 SCK 周期就拿全 `D[13:0]` ⇒ 帧长度 14 bit、掩码 `0x00003FFF` |
| **没有命令字**（从机没有 MOSI） | 发送数据 `RESPONSE_1 = 0`，发什么都没有意义 |
| **CS 上升沿是帧边界** | CSN 高电平 `SPI_CSH_CNT = 16` 给编码器留复位/准备时间（实际空闲 ≈7.5 µs） |
| 时钟由主机决定，越快帧越短 | 14 个 SCK 周期 @2 MHz = 14 × 0.50 µs = 7.0 µs；但一帧总时长还要加帧间空闲 ≈7.5 µs ⇒ ≈14.5 µs/帧（≈68.8 kHz），仍远快于 25 kHz 电流环 |
| 单向、无重传 | 出错只能靠 CRC-6（`x⁶+x+1`）事后校验，且**只有 24 bit 预设才看得到** |
| 无地址、无写操作 | **就是〇节那句话：这一页配的是 TMC6460，编码器一个字节都不写** |

> 也正因为 SSI 是"主机配时序"，本页才会出现 `SPI_BIT_CNT`、`CPOL/CPHA`、`SCK`、`SPI_CSH_CNT`、`RESPONSE_2 掩码` 这类参数——它们全在主机（TMC6460）侧。

## 三、逐值解释（含义 / 为什么是这个值 / 怎么用）

### 1. 极对数 `PHI_E_MUL_FACTOR` = 1 → 写 `0x250[7:0]`

- **去向**：**TMC6460** · `0x250[7:0]`；编码器侧不写任何东西。
- **含义**：编码器测的是**机械角**，FOC 要的是**电角度**。手册 0x242 原文：*"Offset … applied **after multiplying** the angle of the selected channel by PHI_E_MUL_FACTOR"*，即

  ```
  φ_e = 机械角 × 极对数 + 电角度偏置     （偏置是"加"，不是"减"）
  ```

  偏置本身可以是负偏移（16 位无符号寄存器按模 65536 处理）。
- **为什么是 1**：Tesla 手电机是 1 对极（遗留固件 `TMC6460_N_POLE_PAIRS = 1`）。所以页面右侧两个仪表 MECHANICAL 与 ELECTRICAL 的角度/转速**完全一样**——这是正常的，不是 bug。
- **怎么写**：`0x250 = (1<<22) | poles = 0x00400001`（bit22 选周期测速，低字节放极对数）。
- **怎么用**：填 **极对数**，不是极数。4 极电机填 2。填错 → 换相错、抖动 / 堵转。

### 2. 编码器步数 `CPR` = 16384 → 写 `0x240`

- **去向**：**TMC6460** · `0x240`（`SRC_SEL_A=7` + `CPR_INV=1024`）；编码器侧不写。
- **含义**：一圈多少个角度计数。16384 = 2^14，正是 MT6701 的 14 位分辨率，即 **0.02197°/count**。
- **为什么关键**：芯片据此算 `CPR_INV = 2^24 / CPR = 2^24/16384 = 1024`，写进 `0x240[23:0]`，同时 `SRC_SEL_A = 7` 选「外部角度输入 PHI_EXT_A」：

  ```
  0x240 = (7 << 24) | 1024 = 0x07000400
  ```

- **内部换算**（手册 p.180）：`缩放后 = 角度 × CPR_INV >> 8 = 角度 × 4` → 16384 变成 **65536 counts/圈**（0.0055°/LSB），正好铺满 16 位，与遗留固件 `TMC6460_POS_PER_REV = 65536` 对上。
- 界面上**不显示** `CPR_INV`：它完全由 `CPR` 算出来（`2^24 / CPR`），填错 CPR 只会让换算错，不需要单独核对。

### 3. 电角度偏置 `0x242` = 灰显「待对齐」

- **去向**：**TMC6460** · `0x242[15:0]`（本步**跳过**，不写）；与编码器无关。
- **含义**：编码器零点与转子磁极零点之间的**电角度差**，单位 1/65536 电周期（≈0.0055°e），16 位无符号。
- **为什么空着**：每台电机装磁铁的相位都不一样（遗留表 TMC_01…TMC_18 的 14 个值从 `0x0E0F` 到 `0xF847` 各不相同）。**新电机套旧值 = 换相偏 → 可能直接飞车**。所以代码里这一项只在 `write_phi_e_offset = true` 时才写。
- **怎么得到**：下一步「对齐与闭环 → 电角度对齐」，给固定电流把转子拖到几个已知电角度，拟合出 offset 后自动写回 `0x242`。
- **怎么复用**：只有给**同一台已知好板子**复现时才在「写入已知偏移」下拉里选 `TMC_xx`（会自动取消上面的勾选并填值），或选「— 手动 —」。

### 4. 帧长度 `SPI_BIT_CNT` = 14 bit · 角度 → 写进 SPI 命令字 `u[4:0]`

- **去向**：**TMC6460** · `IO_COMMAND(0x381)` 的 `u[4:0]`（值是 14−1=13）。手册：`SPI_BIT_CNT = COMMAND[12:8] + 1`，**上限 32**。它决定 **TMC6460 给 MT6701 打多少个 SCK 周期**；编码器只是被读，不改任何配置。
- **含义**：每帧打多少个 SCK、取多少位。
- **为什么 14**：MT6701 SSI 全帧是 24 个 SCK 周期 = `D[13:0] 角度 + Mg[3:0] 磁场状态 + CRC[5:0]`，MSB 先出。**前 14 个 SCK 周期正好是纯角度**，拿完就走，帧更短、速率上限更高（遗留固件同为 `TMC6460_SPI_BITS = 14`）。
- **代价**：14 bit 模式**看不到 Mg 状态与 CRC 校验**；想自检就切 `24 bit · 全帧`（右侧会多出角度 / Mg / CRC 解码行），但 `CPR_INV` 的语义会变，不确定就退回 14 bit。

### 5. SPI 模式 = 模式 1（CPOL=0 / CPHA=1）

- **去向**：**TMC6460** · `IO_COMMAND` 的 `[27:26]`（IO 控制器在哪个时钟沿采样）；编码器侧不写。
- **手册原话**（MT6701 §7.8.1）：「通信起始于 CSN 的下降沿，在 **CLK 的上升沿发送数据**，CSN 拉高后整个通信停止」，并明确「建议在 **CLK 的下降沿采集数据**」。上升沿出数、下降沿采样 → CPOL=0 / CPHA=1 = **模式 1** ✓。写错 → 读到的值整体错位 / 乱跳。
- **为什么界面上改不了**：MT6701 的寄存器表里没有 SPI 模式位（只有 `OUT_MODE`/`ABZ_MUX`/`UVW_MUX`/`DIR`/`HYST` 等），时序边沿是芯片硬性行为，所以这一项随预设固定、做成只读；点它会弹一句说明。

### 6. SCK 频率 = 2 000 000 Hz，提示 `half=14 → 2.00 MHz`

- **去向**：**TMC6460** · `IO_COMMAND` 的 `[7:0]`（half）。时钟由 TMC6460 的 IO 控制器产生，编码器只跟着时钟出数。
- **含义**：真正写进芯片的**不是频率，而是"SCK 的 0.5 个周期"的计数值 `half`**；界面上那个 2 000 000 只是"目标频率"，芯片落地的是最接近的整数 `half`，提示里的 `half=14 → 2.00 MHz` 就是反算回来的实际值。

**先统一记号（后面一律用小数，不再说"半个/一个"）**

| 记号 | 含义 | 相对 SCK 周期 | 2 MHz 时的值 |
|---|---|---|---|
| `T_clk` | IO 控制器的 1 个 60 MHz 时钟周期 | — | 0.0167 µs（16.7 ns） |
| `T_half` | 寄存器 `half` 控制的那个间隔 | **0.5 个 SCK 周期** | 0.25 µs |
| `T_sck` | SCK 的 **1 个完整周期**（高 + 低） | 1.0 个 SCK 周期 | 0.50 µs |

**公式**

```
T_half = (half + 1) × T_clk          ← 寄存器 half 直接控制这 0.5 个周期
T_sck  = 2 × T_half                  ← 1 个完整周期 = 2 倍上面那 0.5 个周期
f_sck  = 1 / T_sck = 60 MHz / (2 × (half + 1))
```

**为什么有个 +1**：寄存器里存的是"**额外等待的时钟个数**"，不是总数——写 N 表示这一段要数 **N+1** 个 `T_clk`。

**反解 + 代回校验**

```
half   = 60 MHz / (2 × 2 MHz) − 1 = 15 − 1 = 14
T_half = (14 + 1) × 0.0167 µs = 0.25 µs        ← 0.5 个 SCK 周期
T_sck  = 2 × 0.25 µs = 0.50 µs                 ← 1.0 个 SCK 周期
f_sck  = 1 / 0.50 µs = 2.00 MHz                ← 校验通过
```

最容易看错的就是那个 **−1**：要 15 个 `T_clk` 的 `T_half`，寄存器里写的是 **14**。

**它是量化的**（`half` 只能取 0…255 的整数，所以频率是离散的）：

| half | `T_half`（0.5 个周期） | `T_sck`（1.0 个周期） | 实际 SCK |
|---|---|---|---|
| 0 | 0.017 µs | 0.033 µs | 30.00 MHz（理论值，编码器根本跟不上） |
| 9 | 0.167 µs | 0.333 µs | 3.00 MHz（界面允许的上限） |
| 13 | 0.233 µs | 0.467 µs | 2.14 MHz |
| **14** | **0.250 µs** | **0.500 µs** | **2.00 MHz** |
| 15 | 0.267 µs | 0.533 µs | 1.88 MHz |
| 255 | 4.267 µs | 8.533 µs | 117.2 kHz（界面允许的下限） |

界面上 SCK 输入框的 `min = 117 188 Hz`（对应 half=255）与 `max = 3 MHz`（对应 half=9；`spiHzFromHalf` 里 half<10 直接按 3 MHz 显示）就是这两个边界。

- **为什么 2 MHz**：遗留固件就是 `TMC6460_SPI_FREQ_HZ = 2000000`，台架验证过。MT6701 手册 §7.8.1 的时序下限是 `TCLK ≥ 64 ns`（≈ **15.6 MHz**）、`TCLKH/TCLKL ≥ 30 ns`，2 MHz（`T_sck = 0.50 µs`）离上限还有 7.8 倍余量。14 个数据位 = 14 个完整 SCK 周期 = 14 × 0.50 µs = **7.0 µs/帧**；再快对 25 kHz 控制环没有收益，反而拉高单端短线的误码率。

### 7. CSN 高电平 `SPI_CSH_CNT` = 16

- **去向**：**TMC6460** · `IO_COMMAND` 的 `[23:16]`；片选也是 TMC6460 拉出来的，编码器不接收配置。
- **含义**：帧与帧之间（CSN = 1 时）**等多少个系统时钟**再发下一帧（手册 p.115，取值 0…255）。
- **⚠️ 它**不是**线性对应"半个 SCK 周期"**：手册明确 `tSPI_CSH` **与计数的平方成正比**，并且**最短 6 µs**：

  ```
  tSPI_CSH > SPI_CSH_CNT × (SPI_CSH_CNT + 1) / fSYS + tSPI_CSH_OFST      fSYS = 60 MHz
  tSPI_CSH 最短 6 µs；tSPI_CSH_OFST ≈ 3 µs（重复请求 10b）/ ≈ 2 µs（两帧请求 01b）
  ```

  所以 `16` 折合 `16×17/60 MHz + 3 µs ≈ 4.5 + 3 = 7.5 µs`，**不是** 8 个 SCK 周期（4 µs）。而且它不随 SCK 频率变——这是系统时钟域的事。

- **这个 16 不是算出来的**：来自遗留固件 `TMC6460_SPI_IDLE_TIME = 16`，台架跑通值；24-bit 预设用 48 同理。照预设用即可。

- **能算的是"够不够 / 读取率多高"**：

  ```
  帧内传输 = 14 个完整 SCK 周期 × 0.50 µs = 7.0 µs
  帧间空闲 = max(6 µs, 16×17/60 MHz + 3 µs) = 7.5 µs
  一帧合计 = 7.0 + 7.5 = 14.5 µs   ⇒  读取率约 68.8 kHz
  ```

  68.8 kHz 约为 25 kHz 电流环（40 µs/次）的 **2.75 倍**，够用。MT6701 手册 §7.8.1 只要求帧间 `TH ≥ 100 ns`（CSN 上升沿→下一个 CLK 下降沿），这里 7.5 µs 有几十倍余量——**瓶颈不在编码器，在 TMC6460 的 `tSPI_CSH` 机制本身**。

  **这个读取率界面已经自动算好并显示在「CSN 高电平」标签右上角**（`≈68.8 kHz 读取率`），改「帧长度 / SCK 频率 / CSN 高电平」任一个都会实时重算——不需要手算。

- **怎么调**：受平方关系影响，**调大 1 倍约等于空闲时间变 4 倍**——`16 → 32` 会让空闲从 7.5 µs 涨到 ~20 µs。想提高读取率主要靠 `CSN 高电平` 变小，但手册给的下限是 6 µs，所以 **CSH 再小也压不到 6 µs 以下**；这时该提 SCK 频率而不是继续压 CSH。

### 8. 数据掩码 `RESPONSE_2` = `0x00003FFF`（只读，随帧长度派生） → 写 `0x384`

- **去向**：**TMC6460** · `IO_RESPONSE_2(0x384)`。作用在 TMC6460 **收到的字**上，编码器不感知。
- **含义**：把收到的数据帧**按"保留位 = 1、丢弃位 = 0"过滤，再把没被丢弃的位右移拼成一个新数**塞进 `PHI_EXT_A(0x24D)`（手册 Table 55）。所以 14 bit 预设的 `0x00003FFF` = 14 位全留，收到的 `D[13:0]` 原样变成 `PHI_EXT_A` 的低 14 位。
- **为什么**：14 个 SCK 周期时，收满一帧后寄存器里高 18 位是残值 / 垃圾，掩掉后角度不会被污染。
- **⚠️ 24 bit 预设的 `0x00FFFFFF` 是"全留"，不是"取角度"**：24 拍里角度其实在 `[23:10]`（`D[13:0]` 先出），真正的"取角度"掩码是 **`0x00FFFC00`**——硬件会把它右移回 `[13:0]`。现在预设保留全 24 位，`PHI_EXT_A` 就变成"角度+状态+CRC 的原始字"，用来在「角度回读」里解码 Mg/CRC 做诊断；**这种模式下 `CPR_INV` 的换算语义不对，不能拿去闭环**。
- **不再手填**：14 bit 模式下它由帧长度唯一决定（`2^位长 − 1`），界面里是灰显的派生值。以前是可编辑输入框，手改「帧长度」而没同步掩码会读出高位全 0 的假角度。

### 9. 发送数据 `RESPONSE_1` = `0x00000000` → 写 `0x383`

- **去向**：**TMC6460** · `IO_RESPONSE_1(0x383)`，这是 TMC6460 侧准备的 MOSI 载荷。因为 MT6701 不需要命令字，实际线上发的是 0 —— **编码器仍然一个寄存器都没被写**。
- **含义**：主控（TMC6460）往编码器 MOSI 上发的字。
- **为什么是 0**：MT6701 是**纯 SSI 从机**，不需要命令字，给时钟就吐数据。0 表示「不发命令」。
- **为什么界面上改不了**：芯片 SSI 只有 `CSN` / `CLK` / `DO` 三根线（手册引脚表），**没有 SDI/MOSI**，发什么都没人收，所以这一项也随预设固定、做成只读；点它会弹一句说明。

### 10. 片选固定走 ENC_N（预设名后缀 `- ENC_N`，无开关）

- **去向**：**TMC6460** · 引脚复用 `IO_MATRIX(0x006)` + `IO_COMMAND` 的 `u[7]`；编码器侧不写。
- **含义**：`u` 字节里 `[4:0]` = 位长−1（`SPI_BIT_CNT = u[4:0] + 1`，上限 32），`[7]` = **把 CSN 与 SDO 在 `DIRECT_OUT[1]` 和 `DIRECT_OUT[2]` 之间对调**（手册 Table 53）：

  | `u[7]` | CSN | SCK | SDO |
  |---|---|---|---|
  | 0 | `DIRECT_OUT[2]` | `DIRECT_OUT[0]` | `DIRECT_OUT[1]` |
  | **1** | **`DIRECT_OUT[1]`** | `DIRECT_OUT[0]` | `DIRECT_OUT[2]` |

  再叠上本板的 `IO_MATRIX(0x006)`：`ENC_A→DIRECT_OUT0`、`ENC_B→DIRECT_IN0`、`ENC_N→DIRECT_IN1_OUT1`、`HALL_W→DIRECT_OUT2`。所以 **`u[7]=1` ⇒ CSN 走 `ENC_N`、SDO 走 `HALL_W`**（`u[7]=0` 则反过来）。写进命令字 `u = (14−1) | 0x80 = 0x8D`。
- **为什么**：这块板编码器 CS 实际接在 ENC_N，是硬接线，所以界面不再给开关，`u[7]=1` 恒成立（预设名里的 `- ENC_N` 就是提示这件事）。接错 → `PHI_EXT_A` 恒为 0（页面会黄色报警「PHI_EXT_A 为 0」）。
- **副作用**：`DIRECT_OUT[2]` 全芯片只挂在 `HALL_W` 上，所以 `u[7]=1` 时 **SDO 占用了 HALL_W**——这正是手册说的"用 SPI/SSI 编码器就得放弃霍尔/第二路反馈"的原因。

### 11. PWM MAX_COUNT = 4800

- **去向**：**TMC6460** · `0x103[15:0]`（整字写 `0xFFFF12C0`，高 16 位是 Kirchhoff 限幅）；与编码器无关。
- **它是什么**：SVPWM 的**周期计数终值**——计数器从 0 数到 `MAX_COUNT` 再归零，归零一次就是 1 个 PWM 周期。所以它决定**载波频率**，不是占空比。

**怎么算**

```
T_pwm = MAX_COUNT / f_PLL = 4800 / 120 MHz = 40.0 µs      ← 1 个 PWM 周期
f_pwm = 1 / 40.0 µs = 25.0 kHz
```

即 `f_pwm = 120 MHz / MAX_COUNT`。

**为什么这里用 120 MHz，而 SPI 用 60 MHz**（最容易绕晕的地方）

芯片里是两个时钟域，不是同一个：

| 时钟 | 频率 | 谁在用它 |
|---|---|---|
| `f_PLL` | **120 MHz** | PWM / SVPWM 计数、调制 → 所以 4800 → 25 kHz |
| `f_SYS` | **60 MHz** | UART 波特率、IO 控制器（SPI/SSI 时序）→ 所以 `half` 按 60 MHz 算 |

两者正好是 2 倍关系（`f_SYS = f_PLL / 2`）。遗留固件注释写的「`60 MHz / 4800 = 12.5 kHz`」就是把这两个域搞混了，**以 120 MHz → 25 kHz 为准**。

**它是量化的**（MAX_COUNT 只能取整数，界面范围 600…20000）：

| MAX_COUNT | 1 个 PWM 周期 | f_PWM |
|---|---|---|
| 2400 | 20.0 µs | 50.0 kHz |
| **4800** | **40.0 µs** | **25.0 kHz** |
| 9600 | 80.0 µs | 12.5 kHz |
| 20000 | 166.7 µs | 6.0 kHz |

同时它也是**占空比分辨率**：`1 / 4800 ≈ 0.021 %`——MAX_COUNT 越大，能调得越细。

**为什么偏偏是 4800**

- 遗留上位机就是以 `0x103 = 0xFFFF12C0`（`0x12C0` = 4800）下发的，台架验证过；
- 25 kHz 在**人耳可闻上限之上**，不会听到 PWM 啸叫；
- 再高 → 开关损耗/驱动发热上升；再低 → 电流纹波变大，纹波估算 `ΔI_pp ≈ V_bus · D(1−D) / (L · f_pwm)`（Tesla 电机 L ≈ 112 µH），载波减半纹波就翻倍。

**改它的连锁反应**（所以「别动」）

改 MAX_COUNT = 改**整个控制环的时基**：电流环执行频率、速度环分频（`VELOCITY_SAMPLING`）、周期测速的计数基准、RTMI 采样率、阶跃/扫频的分析窗口，全都跟着变；PID 的 **I 项是按 `1/f_pwm` 折算的**（界面里 `I = Ki / f_pwm × 256`），载波一变就必须重算，否则超调/振荡。

### 12. CSA 增益 = `4× · ±1.65 A`

- **去向**：**TMC6460** · `0x0C3[1:0]`；与编码器无关。
- **它是什么**：CSA = 电流采样放大器。`0x0C3[1:0]` 就是放大倍数：`0 = 1×`、`1 = 2×`、`2 = 3×`、`3 = 4×`；**复位默认值是 0（1×）**，不显式写就是 1×。
- **手册原话**（p.76）：*"CSA gain settings are transparent for the raw current values I1, I2, and I3. Higher gain values result in higher resolution of the raw values measured by the internal ADC, whereas lower gain values allow for a higher current to be measured."*
  即：**增益不改变 mA/LSB**（电流数值的刻度是固定的），只改**能测到的最大电流**——增益越高越早饱和，模拟精度越好。

**档位与量程**（数据手册 Table 21，`LS_RES_ON = 11`（55 mΩ）那一列）

| 档位 | `0x0C3[1:0]` | ADC 可测最大电流 | 裁切 count 上限（= 2¹⁵/增益） |
|---|---|---|---|
| 1× | 0 | 6.60 A | 32768 |
| 2× | 1 | 3.30 A | 16384 |
| 3× | 2 | 2.20 A | 10923 |
| **4×** | **3** | **1.65 A** | **8192** |

**mA/LSB 是常数，不随增益变**：Table 20 只跟 `LS_RES_ON` 有关——

```
LS_RES_ON = 11（55 mΩ）：ICSx[A] = Ix × 0.00164 / 8 × 4/4 × 0.982 = Ix × 0.20131 mA
```

所以四档都是 **0.20131 mA/LSB**，差别只在"能数到多少"。

**32768 与 8192 的出处**

- `2^15 = 32768`：电流原始值 I1/I2/I3 是 16 位有符号（`−32768 … +32767`），满刻度绝对值 32768。
- **为什么 4× 只剩 8192**：手册紧接着 Table 21 写明 *"The absolute raw value at which the current is clipped is defined by **2¹⁵/gain_factor**."* → `32768 / 4 = 8192`。遗留脚本照抄了这个规则（`tmc6460_upper_pc/phi_e_calibrate.py`）：

  ```python
  MAX_RAW = 8192  # 4x CSA: 32768/4
  ```

- 代回去正好落在 Table 21：
  ```
  32768 × 0.20131 mA ≈ 6.60 A   （1×）
  16384 × 0.20131 mA ≈ 3.30 A   （2×）
  10923 × 0.20131 mA ≈ 2.20 A   （3×）
   8192 × 0.20131 mA ≈ 1.65 A   （4×）
  ```

**先弄清楚 `LS_RES_ON` 是什么、那个"毫欧"是谁的电阻**

`LS_RES_ON` = **Low-Side RESistor ON**，是 `0x101 MCC_CONFIG.GDRV` 的 `[5:4]`，选的是 **TMC6460 内部三相低边功率 MOSFET 的导通电阻 R_DS(on)**——**不是外部分流电阻**。

手册 p.76 原话：

> "The current is measured inside the TMC6460 using **lossless current sensing on all three low-side MOSFETs**."
> "…the internal current sense capabilities **eliminate the need of bulky external power resistors**…"

也就是说：**低边管自己就是采样电阻**。导通时它的 `V = I × R_DS(on)`，芯片用 CSA 去量这个压降。所以"55 mΩ"指的就是**芯片内部单相低边管的导通电阻**（`LS_RES_ON = 11b` 时典型 55 mΩ / 最大 110 mΩ），与外接的 0.5 mΩ/1 mΩ 采样电阻毫无关系。

四档的用意：把低边 FET 的并联程度改一改——

| `LS_RES_ON` | 低边 `R_ON,LS`（typ/max） | 额定满量程 `IFS` | 1 LSB（Table 20） | 1× 时 ADC 上限 |
|---|---|---|---|---|
| 00 | 200 / 400 mΩ | 1.25 A | 0.0513 mA | 1.68 A |
| 01 | 112 / 220 mΩ | 2.50 A | 0.1017 mA | 3.33 A |
| 10 | 78 / 150 mΩ | 3.75 A | 0.1519 mA | 4.98 A |
| **11（默认，本板）** | **55 / 110 mΩ** | **5.00 A** | **0.20131 mA** | **6.60 A** |

- **电阻越小**（11）：导通损耗小、能跑的电流大（IFS 5 A），但采样电压也小 → 小电流时的信噪比差；
- **电阻越大**（00）：采样电压大、小电流分辨率好，但发热多、额定电流只有 1.25 A。

所以这一位是**硬件级的"量程 / 精度 / 损耗"三选一**，不是软件随手能改的（改了 Table 20 的换算系数全变）。

**本板为什么用 `11`（55 mΩ）**

- `LS_RES_ON` 复位默认就是 **3（55 mΩ）**；
- 遗留固件与旧上位机对 `0x101` 都是**读-改-写**，只置 bit31(CP_EN) / bit16(DRV_EN)，从不碰 `[5:4]` → 一直是 3；
- 手册写的 "total RON of **110 mΩ** (high-side + low-side) → 3 A RMS" 也正好对上：低边 55 + 高边 56 ≈ 110 mΩ。

所以本项目的电流刻度 `0.20131 mA/LSB` 对应的是 `LS_RES_ON=11` 这一行，Table 21 要用 `11` 列。

**旧界面为什么标成 `4× · 0.42 A`**

`1.68 A / 0.42 A` 这一对恰好是 Table 21 的 **`LS_RES_ON = 00`（200 mΩ）列**（1×=1.68、4×=0.42）。也就是说旧标注**按 200 mΩ 的分流电阻取了列**，而这块板是 55 mΩ——同一张表、错列。现已改为 55 mΩ 列的 `6.60 / 3.30 / 2.20 / 1.65 A`。

- **注意这条上限的边界**：Table 21 的数值"只代表 ADC 的测量上限"，手册同时提醒输出级最多只保证 **3 A RMS / 5 A FS**（`LS_RES_ON=11` 的 IFS = 5 A）。所以 1× 那 6.60 A 是 **ADC 数得出来**的上限，不是能长期跑的电流。

- **为什么选 4×**：生产固件 [`motor_core.c`](../../../Tesla_hand_temp_176/applications/motor_core.c:547)（`/* 2c. CSA gain = 3 (10V/V) */`）、旧上位机的闭环/整定脚本 [`main.py`](../../../tmc6460_upper_pc/main.py:920) 都写 3；整套电流常数（`maPerCount = 0.20131`、力矩限幅换算）都建立在这个刻度上。**注意旧上位机的编码器序列写的是 0**（[`tmc6460_encoder.py`](../../../tmc6460_upper_pc/tmc6460_encoder.py:107) `wr(0x0C3, 0)`），所以跑完那套序列必须补写 3——本页正是把这一步并进同一次写入。**改成 0（1×）不会更安全**：mA/LSB 不变，只是量程从 ±1.65 A 扩到 ±6.60 A，模拟精度变差，而 800 mA 根本用不上那么大余量。
- **800 mA 限幅是谁定的**：**不是数据手册**，是**本项目的配置常量**——`Tesla_hand_temp_176/applications/motor_config.h:30` 的 `#define TMC6460_DEFAULT_TORQUE_LIMIT 800 /* mA（用户单位） */`。手册只给换算（Table 20/21），不会规定"你这台电机该限多少"。
- **量程够不够**：800 mA = `800 / 0.20131 ≈ 3974` counts，只占 4× 量程（8192 counts）的 48%，很宽裕——**4× 完全装得下 800 mA**，不需要为了量程退回 1×。
- **怎么用**：写完**必须看回读**（「写入校验」表里就有 `0x0C3`，期望 `0x00000003`）。注意 `0x0C3` 的复位默认是 0（1×），所以这块写不进 3 的板子会静默工作在 1×——读数看着正常，量程与保护点却是另一套。

### 13. 另外两个复选框

- **去向**：也是 **TMC6460** ——「速度测量配置」写 `0x244 / 0x245`；「确认写入」只是本软件的二次确认，**不写任何芯片**。两项都不涉及编码器。

| 项 | 图中状态 | 说明 |
|---|---|---|
| 同时写入速度测量配置（0x244 / 0x245） | 不勾 | 勾了会展开两行 HexField，一并写频率测速 / 周期测速配置；不勾则保留芯片现值 |
| 确认写入 IO_MATRIX / IO Controller / FEEDBACK | 不勾 | **必须勾**才能点写入。因为这步会改引脚复用（SCK / SDI / CSN）+ 启动 SPI 轮询，**立即改变换相行为** |

## 四、点下去实际发生了什么（12 步）

1. 桥臂先切 `PWM_OFF`、力矩 / 速度目标清零
2. 停 IO Controller
3. 配 `IO_MATRIX(0x006)`：把 `ENC_A`→`DIRECT_OUT0`、`ENC_B`→`DIRECT_IN0`、`ENC_N`→`DIRECT_IN1_OUT1`、`HALL_W`→`DIRECT_OUT2`，即**把编码器那几个引脚交给 IO 控制器**（芯片自己的 SCK/SDI/SDO 引脚不动）
4. 探测 IO 控制器固件（`0xAA000000` 握手，读 RESPONSE_1）
5. `0x240` 写 `SRC_SEL_A` + `CPR_INV`
6. 可选写 `0x244 / 0x245`
7. `0x250` 写极对数（+ 周期测速）
8. **`0x242` 跳过**（提示"偏移由对齐测得后写回"）
9. `0x103` PWM 周期 + `0x0C3` CSA 增益
10. `0x384` 数据掩码 + `0x383` 发送数据
11. 下发 `IO_COMMAND`
12. 回读 `RESPONSE_0` 与 `PHI_EXT_A` 校验

命令字可以直接算出来（图中这套参数）：

```
IO_COMMAND(0x381) = 0xF6108D0E
  F       = SPI_ENC 特征码
  [27:26] = 01  SPI 模式 1
  [25:24] = 10  持续轮询 → 写入 PHI_EXT_A
  [23:16] = 0x10  CSH = 16
  [15:8]  = 0x8D  u（位长 13 = 14 bit | ENC_N）
  [7:0]   = 0x0E  half = 14 → 2.00 MHz
```

| 寄存器 | 期望 | 说明 |
|---|---|---|
| `0x240` | `0x07000400` | SRC_SEL_A=7 + CPR_INV=1024 |
| `0x250` | `0x00400001` | 周期测速 + 极对数 1 |
| `0x242` | `—`（待对齐） | 本步不写 |
| `0x0C3` | `0x00000003` | CSA 4× |
| `0x103` | 低 16 位 `0x12C0` | MAX_COUNT 4800 |

---

## 五、这一页该怎么用（操作顺序）

1. 先解锁 **ARM** → 勾选「确认写入 IO_MATRIX…」→ 点 **写入编码器配置**，盯「配置流程」12 步全绿。
2. **手转轴验证（不用点任何按钮）**：右侧「角度回读」每 260 ms 自动刷新，用手慢慢转一圈，MECHANICAL 应从 0° 连续走到 360° 再回 0°，`PHI_EXT_A` 同步变化。`PHI_EXT_A = 0` 就是没读到 → 查 SCK / SDO / CSN 接线、`u[7]`、预设是否匹配。
3. 看「写入校验」：4 行 OK、`0x242` 显示"待对齐" = **正确**；出现"差异"先别往下走。
4. 去 **对齐与闭环 → 电角度对齐**（对齐电流 300 mA、步进 90°e、扫描 720°、勾自动写回 0x242）跑一遍，偏移就测出来了。
5. 之后只在复核老板子时才把「写入已知偏移」切成 `TMC_xx` 复现历史值。

---

## 六、三个最容易踩的坑

1. **CSA 增益只改"能测多大"，不改"读数刻度"**：`0x0C3` 复位默认是 **0（1×）**，而且旧上位机的编码器序列 [`tmc6460_encoder.py`](../../../tmc6460_upper_pc/tmc6460_encoder.py:107) 确实会写 `0`——只有固件 [`motor_core.c`](../../../Tesla_hand_temp_176/applications/motor_core.c:547) 和 [`main.py`](../../../tmc6460_upper_pc/main.py:920) 才补成 3（4×）。写不进 3 时芯片静默跑在 1×：**读数不变（原值对增益透明）**，变的是裁切点——`2¹⁵/增益` 从 8192 counts（4×，±1.65 A）变成 32768 counts（1×，±6.60 A），小电流精度同时变差。按 8192 当满量程做保护/校验的逻辑会全部失准，所以必须核对 `0x0C3` 回读。（"读数差 4 倍"是误传。）
2. **IO_MATRIX 一写就生效**：改的是引脚复用，写完必须回头再看一次「角度回读」确认编码器还有数；写的过程中桥臂是 `PWM_OFF`，电机不会自己动，但已装好的手会"掉力"。
3. **24 bit 预设 ≠ 只改位数**：`CPR_INV` 语义、数据掩码、CSH 都跟着变，非必要用 14 bit。
