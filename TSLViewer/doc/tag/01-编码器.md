# 编码器参数（MT6701 · SSI 14-bit）逐值说明

> 对应界面：**编码器**页 → 卡片「编码器参数 / MT6701 · SSI」。
> 本文解释的截图值 = 预设 `MT6701 · SSI 14-bit（台架已验证）` 的默认值，且处于「新电机第一次上电」状态（未写 `0x242`）。
> 实现：页面 [`Encoder.tsx`](../../src/pages/Encoder.tsx)、预设与遗留表 [`presets.ts`](../../src/lib/presets.ts)、真正落盘的 12 步 [`setup_encoder`](../../src-tauri/src/procs.rs:178)；同一组常量的遗留固件版本见 [`motor_config.h`](../../../Tesla_hand_temp_176/applications/motor_config.h:29)。

**一句话结论**：这一页是把「MT6701 的 SSI 时序 + TMC6460 的反馈链路标尺」一次性写进 **TMC6460**——引脚复用与 IO 控制器（谁来产生 SPI 时钟）、反馈通道 A 的标尺（CPR/CPR_INV）、反馈输出（极对数）、执行器与采样参数（PWM 周期、CSA 增益）；**编码器侧没有任何写入**。

## 〇、目的：这一页配的是 TMC6460，不是编码器

**这一页的每一个数值都写进 TMC6460**（上位机经 UART 写它的寄存器）。MT6701 是**纯 SSI 从机、没有任何可写寄存器**——TMC6460 的 IO 控制器只是给它打 SCK，把返回的 14 位角度收进自己的 `PHI_EXT_A(0x24D)`。所以整页没有"写进编码器"的数据；连「发送数据 `RESPONSE_1`」也只是 TMC6460 侧准备的 MOSI 载荷（MT6701 不需要命令字，实际发 0）。

换句话说：**本页 = 教 TMC6460「怎么读编码器」+「怎么把读到的角度换算成电角度」+「顺手设好执行器时基」**，编码器本身一个字节都不改。

| 组别 | 字段 | 数据最终写进 | 地址 / 位域 |
|---|---|---|---|
| 角度标尺 | 编码器步数 CPR | TMC6460 | `0x240` = `SRC_SEL_A[27:24]` + `CPR_INV[23:0]` |
| 角度标尺 | 极对数 | TMC6460 | `0x250[7:0]`（+ bit22 测速源） |
| 角度标尺 | 电角度偏置 | TMC6460（本步**跳过**） | `0x242[15:0]` |
| SPI 时序 | 帧长度 / SPI 模式 / SCK / CSN 间隔 | TMC6460 | `IO_COMMAND(0x381)` 的 `u[4:0]` / `[27:26]` / `[7:0]` / `[23:16]` |
| 引脚复用 | CS 走 ENC_N | TMC6460 | `IO_MATRIX(0x006)` + `IO_COMMAND` 的 `u[7]` |
| 数据搬运 | 数据掩码 / 发送数据 | TMC6460 | `0x384` / `0x383` |
| 执行器与采样 | PWM MAX_COUNT / CSA 增益 | TMC6460 | `0x103[15:0]` / `0x0C3[1:0]` |
| 面板 | 预设 | **不写任何芯片** | 只填界面 |
| 编码器侧 | MT6701 | **没有任何写入**，只被读 | — |

## 一、SSI 是什么（这一页为什么要配"时序"）

**一句话**：SSI（Synchronous Serial Interface）是编码器最常用的**单向同步串行**绝对位置接口——**主机出时钟，从机按位移出整圈绝对角度**；没有地址、没有命令、没有写操作。

**和 SPI 的关系**：电气与时序上就是"只用「主机→从机」方向的 SPI"。通用 SSI 规范常用 RS-422 差分长线传输，而这块板是 **3 线单端**（`SCK / SDO / CSN`；页面报警文案也写「检查 SCK/SDO/CSN 接线」）。所以 TMC6460 里那个叫 `SPI_ENC` 的功能块，配的就是 SSI：**SPI 的时序参数 = SSI 的时序参数**。

**三根线各干什么**：

| 信号 | 方向 | 作用 | 本页对应的值 |
|---|---|---|---|
| `SCK` | TMC6460 → MT6701 | **时钟**。每个上升沿编码器换下一位、每个下降沿主机采样；占空比 50%，空闲为低（CPOL=0）。没有时钟，编码器一位都不出 | `SCK 频率 = 2 MHz`（half=14）、`SPI 模式 1` |
| `SDO` | MT6701 → TMC6460 | **数据**。帧内 MSB 先出 24 位（角度 14 + 状态 4 + CRC 6）。**只出不进**，编码器没有接收脚 | `帧长度 14 bit`、`数据掩码`、回读的 `PHI_EXT_A` |
| `CSN` | TMC6460 → MT6701 | **片选 / 帧同步**。**拉低 = 一帧开始，拉高 = 一帧结束**：低电平期间 SDO 才有效，高电平期间编码器复位移位寄存器、准备下一帧 | `CSN 间隔 16`、`u[7]=1` 决定它走 `ENC_N` 还是 `HALL_W` |

要点：SSI **没有第 4 根 MOSI**——所以「发送数据 `RESPONSE_1`」在本板是空操作；TMC6460 侧那几个引脚（含用不到的 SDI）只是由 `IO_MATRIX(0x006)` 整组切到 IO 控制器，多余的那根不接线。

接线排查顺序（三根断线表现不同）：`PHI_EXT_A` **恒为 0** → 多为 `SCK` 或 `CSN` 没到（没有帧），或 `SDO` 被拉低；**读数乱跳/角度不连续** → 多为 `CSN` 帧边界没建立或 `SCK/SDO` 干扰；**值跳一位、整体偏** → 先怀疑 `SPI 模式`。三根线都正常但一直 0，再查 `u[7]` 与预设是否匹配。

**读一次数的完整过程**（MT6701 + TMC6460）：

1. TMC6460 拉低 CSn（本板走 `ENC_N`）；
2. 打 24 个 SCK（全帧；本页 14 bit 预设**只打前 14 个**）：**编码器在上升沿更新下一位，主机在下降沿采样** → CPOL=0 / CPHA=1 = **模式 1**；
3. 数据 MSB 先出，24 个 SCK 周期（24 位）依次是：

   ```
   bit  23 ……… 10 │ 9 … 6 │ 5 … 0
        D[13:0]   │ Mg[3:0]│ CRC-6
        角度 14 位 │ 状态 4 位│ 校验 6 位
   ```

   ```
   CSn  ‾‾\___________________________________________/‾‾‾‾‾
   SCK  _____/‾\_/‾\_/‾\_ … _/‾\______________________
               ↑上升沿：编码器换下一位
               ↓下降沿：TMC6460 采样        = 模式 1
   SDO  XXXXX=D13=D12= … =D0=Mg3…Mg0=CRC5…CRC0=XXXXXX
        前 14 位＝角度  4 位    6 位
   ```

4. TMC6460 拉高 CSn，空闲计数值 ≥ `SPI_CSH_CNT` 后再读下一帧。

**SSI 的几个性质，正好解释了本页那些值**：

| SSI 性质 | 在本页对应的值 |
|---|---|
| 每帧都是**完整绝对角度**，不累积、不丢步 | `PHI_EXT_A(0x24D)` 直接就是角度；不需要回零/索引 |
| **MSB 先出** → 截断即取高位 | 只打 14 个 SCK 周期就拿全 `D[13:0]` ⇒ 帧长度 14 bit、掩码 `0x00003FFF` |
| **没有命令字**（从机没有 MOSI） | 发送数据 `RESPONSE_1 = 0`，发什么都没有意义 |
| **CS 上升沿是帧边界** | CSN 间隔 `SPI_CSH_CNT = 16` 给编码器留复位/准备时间 |
| 时钟由主机决定，越快帧越短 | 14 个 SCK 周期 @2 MHz = 14 × 0.50 µs = 7.0 µs（24 个 = 12.0 µs），远快于 25 kHz 电流环 |
| 单向、无重传 | 出错只能靠 CRC-6（`x⁶+x+1`）事后校验，且**只有 24 bit 预设才看得到** |
| 无地址、无写操作 | **就是〇节那句话：这一页配的是 TMC6460，编码器一个字节都不写** |

> 也正因为 SSI 是"主机配时序"，本页才会出现 `SPI_BIT_CNT`、`CPOL/CPHA`、`SCK`、`SPI_CSH_CNT`、`RESPONSE_2 掩码` 这类参数——它们全在主机（TMC6460）侧。

## 三、逐值解释（含义 / 为什么是这个值 / 怎么用）

### 1. 极对数 `PHI_E_MUL_FACTOR` = 1 → 写 `0x250[7:0]`

- **去向**：**TMC6460** · `0x250[7:0]`；编码器侧不写任何东西。
- **含义**：编码器测的是**机械角**，FOC 要的是**电角度**：`φ_e = 机械角 × 极对数 − 偏置`。
- **为什么是 1**：Tesla 手电机是 1 对极（遗留固件 `TMC6460_N_POLE_PAIRS = 1`）。所以页面右侧两个仪表 MECHANICAL 与 ELECTRICAL 的角度/转速**完全一样**——这是正常的，不是 bug。
- **怎么写**：`0x250 = (1<<22) | poles = 0x00400001`（bit22 选周期测速，低字节放极对数）。
- **怎么用**：填 **极对数**，不是极数。4 极电机填 2。填错 → 换相错、抖动 / 堵转。

### 2. 编码器步数 `CPR` = 16384 → 写 `0x240`

- **去向**：**TMC6460** · `0x240`（`SRC_SEL_A=7` + `CPR_INV=1024`）；编码器侧不写。
- **含义**：一圈多少个角度计数。16384 = 2^14，正是 MT6701 的 14 位分辨率，即 **0.02197°/count**。
- **为什么关键**：芯片据此算 `CPR_INV = 2^24 / CPR = 2^24/16384 = 1024`，写进 `0x240[23:0]`，同时 `SRC_SEL_A = 7` 选「外部角度输入 PHI_EXT_A」：

  ```
  0x240 = (7 << 24) | 1024 = 0x07000400
  ```

- **内部换算**（手册 p.180）：`缩放后 = 角度 × CPR_INV >> 8 = 角度 × 4` → 16384 变成 **65536 counts/圈**（0.0055°/LSB），正好铺满 16 位，与遗留固件 `TMC6460_POS_PER_REV = 65536` 对上。
- 界面上那行小字 `14 拍只取角度位，CPR_INV=1024，与遗留固件一致` 说的就是这件事（那里的"14 拍"= 14 个 SCK 周期 = 14 位）。

### 3. 电角度偏置 `0x242` = 灰显「待对齐」

- **去向**：**TMC6460** · `0x242[15:0]`（本步**跳过**，不写）；与编码器无关。
- **含义**：编码器零点与转子磁极零点之间的**电角度差**，单位 1/65536 电周期（≈0.0055°e），16 位无符号。
- **为什么空着**：每台电机装磁铁的相位都不一样（遗留表 TMC_01…TMC_18 的 14 个值从 `0x0E0F` 到 `0xF847` 各不相同）。**新电机套旧值 = 换相偏 → 可能直接飞车**。所以代码里这一项只在 `write_phi_e_offset = true` 时才写。
- **怎么得到**：下一步「对齐与闭环 → 电角度对齐」，给固定电流把转子拖到几个已知电角度，拟合出 offset 后自动写回 `0x242`。
- **怎么复用**：只有给**同一台已知好板子**复现时才在「写入已知偏移」下拉里选 `TMC_xx`（会自动取消上面的勾选并填值），或选「— 手动 —」。

### 4. 帧长度 `SPI_BIT_CNT` = 14 bit · 角度 → 写进 SPI 命令字 `u[4:0]`

- **去向**：**TMC6460** · `IO_COMMAND(0x381)` 的 `u[4:0]`（值是 14−1=13）。它决定 **TMC6460 给 MT6701 打多少个 SCK 周期**；编码器只是被读，不改任何配置。
- **含义**：每帧打多少个 SCK、取多少位。
- **为什么 14**：MT6701 SSI 全帧是 24 个 SCK 周期 = `D[13:0] 角度 + Mg[3:0] 磁场状态 + CRC[5:0]`，MSB 先出。**前 14 个 SCK 周期正好是纯角度**，拿完就走，帧更短、速率上限更高（遗留固件同为 `TMC6460_SPI_BITS = 14`）。
- **代价**：14 bit 模式**看不到 Mg 状态与 CRC 校验**；想自检就切 `24 bit · 全帧`（右侧会多出角度 / Mg / CRC 解码行），但 `CPR_INV` 的语义会变，不确定就退回 14 bit。

### 5. SPI 模式 = 模式 1（CPOL=0 / CPHA=1）

- **去向**：**TMC6460** · `IO_COMMAND` 的 `[27:26]`（IO 控制器在哪个时钟沿采样）；编码器侧不写。
- **为什么**：MT6701 是 **SCK 上升沿更新数据、下降沿采样**，对应 CPOL=0、CPHA=1。写错 → 读到的值整体错位 / 乱跳。

### 6. SCK 频率 = 2 000 000 Hz，提示 `half=14 → 2.00 MHz`

- **去向**：**TMC6460** · `IO_COMMAND` 的 `[7:0]`（half）。时钟由 TMC6460 的 IO 控制器产生，编码器只跟着时钟出数。
- **含义**：真正写进芯片的**不是频率，而是"SCK 的 0.5 个周期"的计数值 `half`**；界面上那个 2 000 000 只是"目标频率"，芯片落地的是最接近的整数 `half`，提示里的 `half=14 → 2.00 MHz` 就是反算回来的实际值。

**先统一记号（后面一律用小数，不再说"半个/一个"）**

| 记号 | 含义 | 相对 SCK 周期 | 2 MHz 时的值 |
|---|---|---|---|
| `T_clk` | IO 控制器的 1 个 60 MHz 时钟周期 | — | 0.0167 µs（16.7 ns） |
| `T_half` | 寄存器 `half` 控制的那个间隔 | **0.5 个 SCK 周期** | 0.25 µs |
| `T_sck` | SCK 的 **1 个完整周期**（高 + 低） | 1.0 个 SCK 周期 | 0.50 µs |

**公式**

```
T_half = (half + 1) × T_clk          ← 寄存器 half 直接控制这 0.5 个周期
T_sck  = 2 × T_half                  ← 1 个完整周期 = 2 倍上面那 0.5 个周期
f_sck  = 1 / T_sck = 60 MHz / (2 × (half + 1))
```

**为什么有个 +1**：寄存器里存的是"**额外等待的时钟个数**"，不是总数——写 N 表示这一段要数 **N+1** 个 `T_clk`。

**反解 + 代回校验**

```
half   = 60 MHz / (2 × 2 MHz) − 1 = 15 − 1 = 14
T_half = (14 + 1) × 0.0167 µs = 0.25 µs        ← 0.5 个 SCK 周期
T_sck  = 2 × 0.25 µs = 0.50 µs                 ← 1.0 个 SCK 周期
f_sck  = 1 / 0.50 µs = 2.00 MHz                ← 校验通过
```

最容易看错的就是那个 **−1**：要 15 个 `T_clk` 的 `T_half`，寄存器里写的是 **14**。

**它是量化的**（`half` 只能取 0…255 的整数，所以频率是离散的）：

| half | `T_half`（0.5 个周期） | `T_sck`（1.0 个周期） | 实际 SCK |
|---|---|---|---|
| 0 | 0.017 µs | 0.033 µs | 30.00 MHz（理论值，编码器根本跟不上） |
| 9 | 0.167 µs | 0.333 µs | 3.00 MHz（界面允许的上限） |
| 13 | 0.233 µs | 0.467 µs | 2.14 MHz |
| **14** | **0.250 µs** | **0.500 µs** | **2.00 MHz** |
| 15 | 0.267 µs | 0.533 µs | 1.88 MHz |
| 255 | 4.267 µs | 8.533 µs | 117.2 kHz（界面允许的下限） |

界面上 SCK 输入框的 `min = 117 188 Hz`（对应 half=255）与 `max = 3 MHz`（对应 half=9；`spiHzFromHalf` 里 half<10 直接按 3 MHz 显示）就是这两个边界。

- **为什么 2 MHz**：遗留固件就是 `TMC6460_SPI_FREQ_HZ = 2000000`，台架验证过，远低于 MT6701 上限。14 个数据位 = 14 个完整 SCK 周期 = 14 × 0.50 µs = **7.0 µs/帧**；再快对 25 kHz 控制环没有收益，反而拉高单端短线的误码率。

### 7. CSN 间隔 `SPI_CSH_CNT` = 16

- **去向**：**TMC6460** · `IO_COMMAND` 的 `[23:16]`；片选也是 TMC6460 拉出来的，编码器不接收配置。
- **含义**：**帧与帧之间 CS 保持高电平的空闲计数**（手册 p.114 的 `SPI_CSH_CNT`，取值 0…255），单位与 `half` 相同，即 1 个计数 = `T_half` = 0.5 个 SCK 周期。
- **它不是算出来的**：这个 16 跟 `half` 不一样，**没有公式可推**——它直接来自遗留固件 `TMC6460_SPI_IDLE_TIME = 16`，是台架上跑通的组合；24-bit 预设用 48 同理。界面上照预设用就行，不需要你推导。
- **能算的是"够不够"**：

  ```
  帧内传输   = 14 个完整 SCK 周期 × 0.50 µs = 7.0 µs
  CS 高电平  = 16 × 0.5 个周期 = 8.0 个 SCK 周期 = 8.0 × 0.50 µs = 4.0 µs
  一帧合计   = 7.0 + 4.0 = 11.0 µs  ⇒  读取率上限约 90.9 kHz
  ```

  90.9 kHz 是 25 kHz 电流环（40 µs/次）的 3.6 倍，余量充足（旧上位机手册把这一档记作「idle < 6.4 µs」）。**这个读取率界面已经自动算好并显示在「CSN 间隔」标签右上角**（`≈90.9 kHz 读取率`），改「帧长度 / SCK 频率 / CSN 间隔」任一个它都会实时重算——不需要手算。
- **怎么调**：调大 → 帧周期变长、读取率下降；调小 → MT6701 来不及在 CS 上升沿后复位移位寄存器，表现为角度**偶发跳变**。真出现跳变，先按 16 → 24 → 32 → 48 往上试。
- **注意耦合**：这个计数折的是同一个 `T_half`，**改了 SCK 频率，同样的 16 代表的绝对时间（4.0 µs）也跟着变**。

### 8. 数据掩码 `RESPONSE_2` = `0x00003FFF`（只读，随帧长度派生） → 写 `0x384`

- **去向**：**TMC6460** · `IO_RESPONSE_2(0x384)`。作用在 TMC6460 **收到的字**上，编码器不感知。
- **含义**：IO 控制器收到 24 位词后，**只保留低 14 位**塞进 `PHI_EXT_A(0x24D)`。
- **为什么**：14 个 SCK 周期时高位是残值 / 垃圾，掩掉后角度不会被污染；换成 24 bit 预设时该值会变成 `0x00FFFFFF`。
- **不再手填**：它由帧长度唯一决定（`2^位长 − 1`），界面里是灰显的派生值，随「帧长度」自动变。以前是可编辑输入框，手改「帧长度」而没同步掩码会读出高位全 0 的假角度。

### 9. 发送数据 `RESPONSE_1` = `0x00000000` → 写 `0x383`

- **去向**：**TMC6460** · `IO_RESPONSE_1(0x383)`，这是 TMC6460 侧准备的 MOSI 载荷。因为 MT6701 不需要命令字，实际线上发的是 0 —— **编码器仍然一个寄存器都没被写**。
- **含义**：主控（TMC6460）往编码器 MOSI 上发的字。
- **为什么是 0**：MT6701 是**纯 SSI 从机**，不需要命令字，给时钟就吐数据。0 表示「不发命令」。

### 10. `u[7]=1 · CS 走 ENC_N`（已勾选）

- **去向**：**TMC6460** · 引脚复用 `IO_MATRIX(0x006)` + `IO_COMMAND` 的 `u[7]`；编码器侧不写。
- **含义**：片选信号从 **ENC_N** 引脚出（`u[7]=1`），否则走 `HALL_W`；写进命令字 `u = (14−1) | 0x80 = 0x8D`。
- **为什么**：这块板子编码器 CS 实际接在 ENC_N，台架验证过。选错 → `PHI_EXT_A` 恒为 0（页面会黄色报警「PHI_EXT_A 为 0」）。

### 11. PWM MAX_COUNT = 4800

- **去向**：**TMC6460** · `0x103[15:0]`（整字写 `0xFFFF12C0`，高 16 位是 Kirchhoff 限幅）；与编码器无关。
- **它是什么**：SVPWM 的**周期计数终值**——计数器从 0 数到 `MAX_COUNT` 再归零，归零一次就是 1 个 PWM 周期。所以它决定**载波频率**，不是占空比。

**怎么算**

```
T_pwm = MAX_COUNT / f_PLL = 4800 / 120 MHz = 40.0 µs      ← 1 个 PWM 周期
f_pwm = 1 / 40.0 µs = 25.0 kHz
```

即 `f_pwm = 120 MHz / MAX_COUNT`。

**为什么这里用 120 MHz，而 SPI 用 60 MHz**（最容易绕晕的地方）

芯片里是两个时钟域，不是同一个：

| 时钟 | 频率 | 谁在用它 |
|---|---|---|
| `f_PLL` | **120 MHz** | PWM / SVPWM 计数、调制 → 所以 4800 → 25 kHz |
| `f_SYS` | **60 MHz** | UART 波特率、IO 控制器（SPI/SSI 时序）→ 所以 `half` 按 60 MHz 算 |

两者正好是 2 倍关系（`f_SYS = f_PLL / 2`）。遗留固件注释写的「`60 MHz / 4800 = 12.5 kHz`」就是把这两个域搞混了，**以 120 MHz → 25 kHz 为准**。

**它是量化的**（MAX_COUNT 只能取整数，界面范围 600…20000）：

| MAX_COUNT | 1 个 PWM 周期 | f_PWM |
|---|---|---|
| 2400 | 20.0 µs | 50.0 kHz |
| **4800** | **40.0 µs** | **25.0 kHz** |
| 9600 | 80.0 µs | 12.5 kHz |
| 20000 | 166.7 µs | 6.0 kHz |

同时它也是**占空比分辨率**：`1 / 4800 ≈ 0.021 %`——MAX_COUNT 越大，能调得越细。

**为什么偏偏是 4800**

- 遗留上位机就是以 `0x103 = 0xFFFF12C0`（`0x12C0` = 4800）下发的，台架验证过；
- 25 kHz 在**人耳可闻上限之上**，不会听到 PWM 啸叫；
- 再高 → 开关损耗/驱动发热上升；再低 → 电流纹波变大，纹波估算 `ΔI_pp ≈ V_bus · D(1−D) / (L · f_pwm)`（Tesla 电机 L ≈ 112 µH），载波减半纹波就翻倍。

**改它的连锁反应**（所以「别动」）

改 MAX_COUNT = 改**整个控制环的时基**：电流环执行频率、速度环分频（`VELOCITY_SAMPLING`）、周期测速的计数基准、RTMI 采样率、阶跃/扫频的分析窗口，全都跟着变；PID 的 **I 项是按 `1/f_pwm` 折算的**（界面里 `I = Ki / f_pwm × 256`），载波一变就必须重算，否则超调/振荡。

### 12. CSA 增益 = `4× · 0.42 A`

- **去向**：**TMC6460** · `0x0C3[1:0]`；与编码器无关。
- **它是什么**：CSA = 电流采样放大器。分流电阻上的压降先被它放大，再送进 ADC。`0x0C3[1:0]` 就是放大倍数：`0 = 1×`、`1 = 2×`、`2 = 3×`、`3 = 4×`。
- **为什么重要**：ADC 的输入范围是固定的，增益放大的是**信号**。增益 ×4 → 同样电流给出 4 倍电压 → **每 LSB 代表更小的电流（分辨率好 4 倍）**，但**能测的最大电流也小 4 倍**。这是纯粹的「量程 ↔ 分辨率」取舍，**不改电机力矩**。

**档位与量程**（下拉框里那四个数就是各档量程，严格反比）

| 档位 | `0x0C3[1:0]` | 量程 | 每 LSB 电流 |
|---|---|---|---|
| 1× | 0 | 1.68 A | ≈ 0.805 mA |
| 2× | 1 | 0.84 A | ≈ 0.403 mA |
| 3× | 2 | 0.56 A | ≈ 0.268 mA |
| **4×** | **3** | **0.42 A** | **0.20131 mA** |

换算关系一目了然：`1.68 A / 增益`；每 LSB = 量程 ÷ 2048（4× 时 0.42 A ÷ 2048 ≈ 0.205 mA，与项目常量 `TESLA_PROFILE.maPerCount = 0.20131 mA` 一致，2% 差别来自标称值取整）。

- **为什么选 4×**：Tesla 电机力矩限幅只有 800 mA、常用工作点在几百 mA，量程越小分辨率越有用（300 mA 对齐电流 ≈ 1490 counts，读得清）。**但遗留固件把 `0x0C3` 写成 0（1×）**，本页会写 3 —— 所以**同一股电流，读数会变成 4 倍**，力矩限幅换算、保护阈值全跟着变 4 倍，这是这块板最经典的坑。
- **怎么用**：写完**必须看回读**（「写入校验」表里就有 `0x0C3`，期望 `0x00000003`）。改档位等于改了电流环的增益：`mA → LSB` 的系数变了 4 倍，力矩环的等效 Kp/Ki 也变，要复核 PID（或按新量程重算）。

### 13. 另外两个复选框

- **去向**：也是 **TMC6460** ——「速度测量配置」写 `0x244 / 0x245`；「确认写入」只是本软件的二次确认，**不写任何芯片**。两项都不涉及编码器。

| 项 | 图中状态 | 说明 |
|---|---|---|
| 同时写入速度测量配置（0x244 / 0x245） | 不勾 | 勾了会展开两行 HexField，一并写频率测速 / 周期测速配置；不勾则保留芯片现值 |
| 确认写入 IO_MATRIX / IO Controller / FEEDBACK | 不勾 | **必须勾**才能点写入。因为这步会改引脚复用（SCK / SDI / CSN）+ 启动 SPI 轮询，**立即改变换相行为** |

## 四、点下去实际发生了什么（12 步）

1. 桥臂先切 `PWM_OFF`、力矩 / 速度目标清零
2. 停 IO Controller
3. 配 `IO_MATRIX`(0x006) 的 SCK / SDI / CSN（CS 选 ENC_N）
4. 探测 IO 控制器固件（`0xAA000000` 握手，读 RESPONSE_1）
5. `0x240` 写 `SRC_SEL_A` + `CPR_INV`
6. 可选写 `0x244 / 0x245`
7. `0x250` 写极对数（+ 周期测速）
8. **`0x242` 跳过**（提示"偏移由对齐测得后写回"）
9. `0x103` PWM 周期 + `0x0C3` CSA 增益
10. `0x384` 数据掩码 + `0x383` 发送数据
11. 下发 `IO_COMMAND`
12. 回读 `RESPONSE_0` 与 `PHI_EXT_A` 校验

命令字可以直接算出来（图中这套参数）：

```
IO_COMMAND(0x381) = 0xF6108D0E
  F       = SPI_ENC 特征码
  [27:26] = 01  SPI 模式 1
  [25:24] = 10  持续轮询 → 写入 PHI_EXT_A
  [23:16] = 0x10  CSH = 16
  [15:8]  = 0x8D  u（位长 13 = 14 bit | ENC_N）
  [7:0]   = 0x0E  half = 14 → 2.00 MHz
```

右侧「写入校验」表的期望值：

| 寄存器 | 期望 | 说明 |
|---|---|---|
| `0x240` | `0x07000400` | SRC_SEL_A=7 + CPR_INV=1024 |
| `0x250` | `0x00400001` | 周期测速 + 极对数 1 |
| `0x242` | `—`（待对齐） | 本步不写 |
| `0x0C3` | `0x00000003` | CSA 4× |
| `0x103` | 低 16 位 `0x12C0` | MAX_COUNT 4800 |

## 五、这一页该怎么用（操作顺序）

1. 先解锁 **ARM** → 勾选「确认写入 IO_MATRIX…」→ 点 **写入编码器配置**，盯「配置流程」12 步全绿。
2. **手转轴验证（不用点任何按钮）**：右侧「角度回读」每 260 ms 自动刷新，用手慢慢转一圈，MECHANICAL 应从 0° 连续走到 360° 再回 0°，`PHI_EXT_A` 同步变化。`PHI_EXT_A = 0` 就是没读到 → 查 SCK / SDO / CSN 接线、`u[7]`、预设是否匹配。
3. 看「写入校验」：4 行 OK、`0x242` 显示"待对齐" = **正确**；出现"差异"先别往下走。
4. 去 **对齐与闭环 → 电角度对齐**（对齐电流 300 mA、步进 90°e、扫描 720°、勾自动写回 0x242）跑一遍，偏移就测出来了。
5. 之后只在复核老板子时才把「写入已知偏移」切成 `TMC_xx` 复现历史值。

---

## 六、三个最容易踩的坑

1. **CSA 4× vs 遗留 1×**：本页写 3（4×），遗留固件写 0（1×）→ 电流读数差 4 倍，力矩限幅跟着差 4 倍。
2. **IO_MATRIX 一写就生效**：改的是引脚复用，写完必须回头再看一次「角度回读」确认编码器还有数；写的过程中桥臂是 `PWM_OFF`，电机不会自己动，但已装好的手会"掉力"。
3. **24 bit 预设 ≠ 只改位数**：`CPR_INV` 语义、数据掩码、CSH 都跟着变，非必要用 14 bit。
