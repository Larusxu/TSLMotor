# TeslaHand 机械找零与位置控制适配

日期：2026-11-01。参考桌面 moto/doc 的《1.2-电机找零》《1.3-电机控制》，在现有 TSLViewer 机械找零页面及 TeslaHand 协议上适配。

## 单位与方向

- 页面机构正向对应芯片负向；位置目标与位置/速度反馈统一反号，底层透传寄存器仍是芯片原始值。
- 页面机械找零方向 −1 对应线协议 +1，即本次 M9 成功的回零方向。历史命令行 `--direction 1` 是原始芯片方向，不能与新页面符号混用。
- TMC6460 多圈位置按 65536 count/机械圈换算；MT6701 仍用 SSI 14-bit，不套用参考工程的 32768 count/圈或寄存器地址。
- 电流显示 mA，当前硬件换算 0.20131 mA/count；测速换算 305.4198966 count/RPM。减速比默认51仅作输出端角度显示。

## 实现与调用链

`Homing.tsx → MotorControls / Commissioning → Tauri motor_control_* / run_job("commission") → motor_control.rs / commission.rs → Link → gateway Transport → 485 Modbus封装或USB-CAN-A分包 → CPU0 los_moto → 对应UART → TMC6460`。

供电仍走 `CPU0 LOS_Max20087代理 → MBX/共享SRAM → CPU1 MAX20087 → I2C`，沿用16路映射。未新增应用层MCU头文件、堆分配或RTOS对象。

主控负责现有找零状态机、UART独占和通讯租约；TMC执行位置/速度/电流闭环与硬件限幅。五次位置曲线、点动参考、往复/正弦由桌面Rust工作线程规划，约60ms更新，不能称为主控实时轨迹规划。

## 页面操作

1. 连接主控485或CAN，选对应电机，解锁ARM并开启该路逻辑电源。
2. 本页可展开编码器、PID、EEPROM详细配置，或使用组合标定：完整流程、强制完整流程、重新找零、仅编码器对齐、仅找零。组合流程使用自身显示的PID值，默认来自M9；其它电机需修改。
3. 找零有效后，核对方向、行程、速度及电流限制，确认空间，再启动电机输出。上电与PWM使能是不同动作。
4. 点动按住推进，松开将目标钉在实测位置；绝对位置支持轨迹和直通；工况支持保持、往复、正弦及循环数。停止工况仍保持力矩；停止电机关闭PWM。
5. ESC急停；失焦/隐藏/离开控制页面请求停止；页面心跳超过1秒由Rust工作线程停PWM，失败时请求逻辑断电。物理断线或整个PC进程终止时依赖主控既有5秒通讯租约关断，不能把1秒页面超时当成所有失联场景的硬件停机保证。
6. 关闭逻辑电源会使运行零点失效。可选EEPROM保存的是编码器、电角度、PID等参数，不保存运行零点。

限幅/行程修改须断使能；运行时目标不得超出行程。54600°是参考文档值，未作为本板全行程实测结果。电压和温度当前协议未提供，页面明确显示不可用。

## 固件零点生命周期修复

- 原先写位置目标0x152、限幅0x14c/0x14d、PWM_OFF/普通位置模式会使零点失效，现保留有效零点。
- 改位置原点0x155/0x156、编码器0x240/0x242、电机类型/极对数或非位置运动模式仍使零点失效。
- 原全部断电仅清编码器/对齐标记，漏清已完成找零；现逐路复用单路断电处理，所有有效零点清除。

## 实板验证

正式应用经COM10 DFU更新，最终镜像CRC32 `56FC5EC2`，app.bin SHA256 `3c8cab02be7b056893993814a6e50c80e27895a90e2aa5356ba07015391cb392`。CPU1上线、OTA确认，UART心跳#1～#56连续。

命令行直接执行生产Rust控制后端测试 `motor_control::tests::hardware_m9_control`，没有操作UI或使用模拟器。M9找零：1050mA额定、500mA限流、420mA判据、2000RPM速度上限、退开360°；位置控制：500mA限流、120RPM上限、650mA连续过流阈值、0～1440°窗口。

|---|---|
| 找零 | 成功；退开后位置329.150°，零点有效 |
| 轨迹540° | 541.143° |
| 正向/负向点动 | 位置分别增加至677.351°、减小至598.931° |

实测结束全部逻辑输出关闭、串口释放。原始快照和启动日志在 `application/TeslaHand/doc/test/m9_control_20261101/`。第一轮FAIL记录保留：暴露全部断电零点未清；修复后完整测试PASS。

本次验证功能闭环与保护，不代表机械重复精度已验收；快照仍能观察到保持过程跟踪误差，PID尚需结合负载调优。未验证其它15路运动、全行程、所有组合重标定/EEPROM分支。CAN本轮只做通信回归，完整运动流程走485。

上位机源码通过TypeScript检查、Rust33项单测和前端8项测试；本次没有重新打包桌面EXE，现有EXE不包含新增页面。真实硬件测试默认ignored，需显式端口和报告路径才运行，脚本保留供复测。
