# TODO-02 环路测试（闭环特性验证与参数整定）——主控固件开发说明

> **读者**：主控板固件开发者。
> **目标**：读完这一份就知道「环路测试」页上位机做什么、固件必须保证什么、以及把 `com_moto` 那套老映射搬到 TMC6460 上要改哪几处。
> **参考实现**：`com_moto` 项目 `doc/1.4-环路测试.md`（PyQt + 老主控固件那台机器，判据与流程完全适用）。

---

## 0. 一句话

> **这一页几乎全是上位机的事**：生成恒 Iq / 恒速度 / 位置目标、每 60 ms 读位置判边界、换速度环系数打分选优、采样画波形。
> **固件只负责闭环与裁决**：位置/速度/力矩三个环、限幅、模式仲裁、故障保护、急停后清目标。

**不需要**为这一页新增任何主控协议：上位机只写 TMC6460 的标准寄存器、只读标准反馈寄存器。
所以固件的活只有两件：**① 别让上位机写进去的东西被固件悄悄改掉；② 故障/急停时把目标和积分器清干净。**

上位机已经写好（侧栏 → 调校 →「环路测试」，`src/pages/LoopTest.tsx` + `src/lib/looptest.ts`）。

## 1. 页面结构

| 区块 | 上位机下发什么 | 谁裁决 |
|---|---|---|
| ① 恒 Iq / 恒速度 | `0x100` 切模式、`0x14A` 电流上限、`0x14E`/`0x150` 给定、每 60 ms 读 `0x155` 判边界 | 上位机判边界；芯片限流 |
| ② 速度 PI 自动辨识 | 逐组写 `0x145`、给 ±转速、按评分选优并写回 | 上位机打分；芯片闭环 |
| ③ 位置环测试 | `0x152` 阶跃/往复/正弦目标、`0x14B`/`0x14A`/`0x14C`/`0x14D` 限幅 | 上位机生成目标；芯片闭环 |
| 实时值 / 波形 | 只读 | — |

三个「看起来像固件做、其实在上位机」的判断，务必分清：

1. **边界裁决**：到没到「测试行程」，是上位机读 `0x155` 后自己算的 —— 芯片/固件不知道「测试行程」这个概念；
2. **循环计数**：往复跑了几次，是上位机数时间片算的；
3. **评分与选优**：`J` 由上位机算，最优 Kp/Ki 由上位机写回 `0x145`。

反过来，**「电流上限 300 mA 真的把电流钳住了」是芯片的行为**，上位机只是把计数写进 `0x14A`。

## 2. 上位机用到的全部寄存器

### 2.1 写（每次写都带回读校验）

| 寄存器 | 位域 | 单位 | 用途 |
|---|---|---|---|
| `0x100 MCC_CONFIG.MOTOR_MOTION` | `[12:9]` MOTION_MODE | — | `2`=TORQUE、`3`=VELOCITY、`4`=POSITION、`0`=PWM_OFF |
| | `[14]` RAMP_EN | — | 环路测试**恒为 0**：位置目标直接取 `0x152`，这就是「位置直通」 |
| | `[8:7]` MOTOR_TYPE / `[6:0]` 极对数 | — | 上位机整套写（`regs::motor_motion` 同款布局） |
| `0x101 MCC_CONFIG.GDRV` | `[16]` DRV_EN_BIT、`[31]` 充电泵 | — | 切任何非 PWM_OFF 模式前先置位 |
| `0x145 FOC.PID_VELOCITY_COEFF` | `[31:16]` VELOCITY_P、`[15:0]` VELOCITY_I | 裸系数 | 辨识时逐组写；受 `0x140` 归一化影响 |
| `0x14A FOC.PID_TORQUE_FLUX_LIMITS` | `[30:16]` 力矩上限、`[14:0]` 磁链上限 | LSB（0.20131 mA） | 「电流上限」，**对力矩模式同样生效** |
| `0x14B FOC.PID_VELOCITY_LIMIT` | `[30:0]` | LSB（305.4/RPM） | 位置测试的「速度限制」 |
| `0x14C/0x14D POSITION_LIMIT_LOW/HIGH` | `[31:0]` 有符号 | counts | 位置测试的**硬件护栏**（比测试行程再放宽 1/8） |
| `0x14E FOC.PID_TORQUE_FLUX_TARGET` | `[31:16]` 力矩给定、`[15:0]` 磁链给定 | LSB | 恒 Iq 给定（**有符号 16 位**，别当无符号） |
| `0x150 FOC.PID_VELOCITY_TARGET` | `[31:0]` 有符号 | LSB（305.4/RPM） | 恒速度 / 辨识时的转速给定 |
| `0x152 FOC.PID_POSITION_TARGET` | `[31:0]` 有符号 | counts | 位置环测试目标（每 60 ms 重写） |
| `0x15F FOC.PID_VELOCITY_INTEGRATOR` | `[31:0]` | — | 收尾清积分器 |

### 2.2 读（每 60 ms 一次 `readMany`）

| 寄存器 | 取哪几位 | 换算 | 用途 |
|---|---|---|---|
| `0x155 FOC.PID_POSITION_ACTUAL` | `[31:0]` 有符号 | counts，65536/圈 | 位置 + 边界裁决 |
| `0x154 FOC.PID_VELOCITY_ACTUAL` | `[31:0]` 有符号 | `RPM = raw / 305.4` | 速度反馈（PLL） |
| `0x153 FOC.PID_TORQUE_FLUX_ACTUAL` | `[31:16]` 有符号 | `mA = raw × 0.20131` | Iq 实测 = **速度 PI 输出的代理** |
| `0x159 FOC.PID_VELOCITY_ERROR` | `[31:0]` 有符号 | `RPM = raw / 305.4` | 速度误差（辨评分用） |

> `0x155` 是 **RW**：写它会同时改写 `0x152`（除非 `0x140[0] KEEP_POS_TARGET=1`）。找零/清零点靠写 `0x155`，别误用。

## 3. 固件必须保证的 9 件事

| # | 要求 | 不满足的后果 |
|---|---|---|
| 1 | **模式仲裁**：同一时刻只有一个「运动主人」。上位机正在跑环路测试时，固件不得自己切 `MOTION_MODE`（心跳、状态机、看门狗都不许） | 测试中途被切走，电机行为与界面完全不符，甚至飞车 |
| 2 | **不许覆盖限幅**：固件周期性刷 `0x14A/0x14B` 的话，必须基于「当前值」而不是常量 | 电流上限被改回去，300 mA 变成满流 |
| 3 | **不许覆盖增益**：`0x145` 只在辨识期间由上位机写；固件不得在读 EEPROM 后异步重写 | 辨识结果永远不是最优那一组 |
| 4 | **急停/故障后清干净**：写 `0x14E=0`、`0x150=0`、`0x15F=0`、`0x100=PWM_OFF`、清 `0x101[16]` | 残余目标会在下次使能瞬间满速冲出去 |
| 5 | **故障不自动恢复**：过流/过温/编码器丢失后必须保持故障态，等上位机显式复位 | 上位机还在跑测试，电机反复重启 |
| 6 | **`0x14C/0x14D` 默认值可用**：上电初值 `0x80000001 / 0x7FFFFFFF`；若固件自己维护软行程，也与上位机写入值保持一致 | 上位机写的位置护栏被下一次固件刷新抹掉 |
| 7 | **上报状态要跟 `0x153` 同源**：固件对外的「电流」字段必须来自 `0x153[31:16]` | 界面与固件的电流对不上，排障时会走弯路 |
| 8 | **允许 60 ms 内多次写同一寄存器**：不要对 `0x152`/`0x150` 做「每秒限一次」之类的节流 | 位置目标更新不上，波形变成阶梯 |
| 9 | **转发链路不要过滤寄存器**：主控的 UART 转发是透明透传，这一页因此不需要新增 op。若固件层加过寄存器白名单，必须放开 `0x100/0x101/0x140`–`0x166` 这一段 | 上位机写模式/增益被静默丢弃，测试看起来"没反应" |

## 4. 与 com_moto 老映射的 6 处差异（**兼容改造点**）

| # | 老上位机做法 | TMC6460 上必须改成 | 依据 |
|---|---|---|---|
| 1 | 电流两套刻度：`s16A`（23831/A）与「归一值」（2000=峰值），相差约 12 倍 | **只有一个刻度**：`mA = raw × 0.20131`，满量程 `±8192 LSB ≈ ±1.65 A` | 数据表「电流采样」表 + `LS_RES_ON` |
| 2 | 恒 Iq 走 `mode2`，「电流上限」框**不生效**（`maxcurrent` 只钳速度环输出） | `0x14A[30:16]` 钳的是**力矩控制器目标的绝对值**，力矩模式一样生效 → **恒 Iq 有二级限流** | `0x14A` 寄存器说明（p.163） |
| 3 | 速度环 `Kp_speed`/`Ki_speed` 是裸整数 | `0x145[31:16]/[15:0]`，并受 `0x140` 的 `VELOCITY_NORM_P/I` 影响（Q16.0 / Q8.8 / Q0.16 / Q0.24）。**同一组数字配不同归一化，实际增益差 256 倍** | `0x140` / `0x145`（p.160、p.162） |
| 4 | 遥测里有独立的 `log_speed_pid_out`（速度 PI 输出） | TMC6460 **没有**这个寄存器 → 用 `0x153[31:16]`（力矩实测）代替，同刻度、含积分项 | `0x153`（p.164） |
| 5 | 位置是 16 位、`measuredposition` 单位 Count 且每圈归零 | `0x152/0x155` 是 **32 位多圈**，一圈 65536 counts，不归零、靠写 `0x155` 清零 | `0x155`（p.165）+ 特性表「Multiturn position counter (32 bits)」 |
| 6 | 只有上位机看门（软行程在 PC 里） | 可以再加一道**芯片护栏**：`0x14C/0x14D`。上位机环路测试已经会写它 | `0x14C/0x14D`（p.163） |

> 另外：`0x147/0x148 PID_POSITION_TOLERANCE(_DELAY)` 在老固件里等价于「位置到达判据」。环路测试**不依赖**它（位置误差由上位机把 `0x152` 与 `0x155` 相减得到），所以固件不用为这一页去调它。

## 5. TMC6460 独有能力（将来可以直接用，现在没打开）

| 能力 | 位置 | 价值 |
|---|---|---|
| **PRBS 注入** | `MOTION_MODE = 5…9`（`PRBS_UD / FLUX / TORQUE / VELOCITY / POSITION`） | 频响辨识可以直接让芯片注入，不必上位机逐点下发 —— 比本页的 60 ms 给定快两个数量级 |
| **速度前馈** | `0x100[19] VELOCITY_FF_EN` + `0x151 PID_VELOCITY_OFFSET` | `com_moto` 里 `Kff_vel` 恒为 0（固件没打通）；TMC6460 原生支持，**这是唯一能真正打开前馈的路径** |
| **位置容差** | `0x147 / 0x148` | 「到位」判据交给芯片，比上位机轮询准 |
| **速度双二阶滤波** | `0x120` 段 `VELOCITY_BIQUAD` | 编码器噪声大时可替代 PLL 调参 |

这三项都要求固件先做**模式仲裁**（第 3 节 #1），否则会和上位机抢 `0x100`。

## 6. 已知限制（写进界面提示了，别当 bug）

1. **恒 Iq 没有堵转保护**：判据只看位置越界，机构卡死时位置不动、边界永不触发 → 电机会持续按给定电流堵转。测试时人必须在场。
2. **采样只有 60 ms 一拍**：行程裁决与打点同源，看不到 25 kHz 电流环尺度。要看高频细节用 RTMI 抓 `0x153/0x168`。
3. **评分的三项混量纲**（RPM + RPM + mA）：只能同机同工况排序，不能跨机器比较。
4. **位置测试固定直通**：不用 S 曲线插补，目标是阶跃 → 起步有冲击是**故意的**（就是要看位置环自身响应）。
5. **辨识结束停在 PWM_OFF**：不会自动切回模式，接着做位置测试要重新启动。

## 7. 联调检查清单（固件做完按这个顺序验）

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 连接 + ARM，切到「环路测试」页，不点任何按钮 | 实时值里的位置/速度/模式每 500 ms 刷新一次（只读，不动电机） |
| 2 | ①恒 Iq：填 30 mA（远小于静摩擦）启动 | 电机不动、Iq 稳定在 30 mA、到不了边界会一直跑 → 手动「停止测试」 |
| 3 | ①恒 Iq：逐级加 60 → 100 → 150 mA | 找到「起不来 / 起来 / 开始抖」三个门槛 |
| 4 | ①恒速度：300 RPM，看 Iq | 方向与符号一致；Iq 被 `0x14A` 钳住（把上限调到 50 mA 应明显掉速） |
| 5 | ①边界策略改成「自动换向」 | 到边界后给定反向、往复次数 +1，日志出现「自动换向」 |
| 6 | ③位置环：先「到中心」再「启动位置测试」 | 机构先静止在中心，启动后目标在 A/B 间阶跃，波形里位置是斜坡（=速度限幅在削顶） |
| 7 | ③「停止位置测试」 | 停止下发但仍有力矩（推不动）；再点「停止测试」才卸力 |
| 8 | ②辨识：倍率先只填 `1`（单候选） | 结果表出现一行，`顶限=否`、`J` 有限值 |
| 9 | ②辨识：倍率 `0.5,0.75,1,1.25,1.5` + 勾选「完成后应用最佳」 | 选出一行最优并写回 `0x145`；日志出现「已写回最优 Kp=… Ki=…」 |
| 10 | 任意时刻按急停 | 目标清零、PWM_OFF、界面「测试状态」回到「空闲」，日志出现「■ 结束 …·成功」 |
