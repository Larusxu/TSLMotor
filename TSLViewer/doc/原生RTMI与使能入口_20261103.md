# 原生 RTMI 与使能入口修复（2026-11-03）

## 本轮结果

已修改固件和 TSLViewer 源码，最终 APP CRC **4309215A**，188048 字节（含 0x400 gap），payload 187024 字节；SHA256 `185f050330fdd8d456d256d8b50ba01bd85f1cd5ad2962a2588b73a5a0e9612b`。通过 flash_v2 / tools/hpm_v2 的 DFU APP 升级并收到 CRC OK。不写 boot/factory/OTP，不使用 JTAG。未打包桌面 EXE，未操作用户 UI。

## 界面与使能

- 编码器“写入并回读”保留输入内容，独立比较预期与实际寄存器掩码，更新校验结果/OK；不再用回读覆盖编辑状态。找零参数写入同样保留编辑值并记录已验证快照。
- 电机控制卡片移除内部分隔线及“确认机构…独立裁决”勾选项。找零参数放左边，找零控制放右边。
- “采样周期”改为“保护采样周期”：这是 MCU 反馈/持续过流检测周期，与 RTMI 曲线采样分开。改变它会改变过流观察节拍，不代表 RTMI 发送速度。
- 右上角主控模式原入口仍发送旧网关 op5；新执行器不接受该旧写入口。改用语义 initialize，并核验 logic_power/config_verified/limits_valid。此处表示初始化就绪，保持驱动禁能；真实运动仍须运动授权。直连模式保留原探测流程。

## RTMI 数据链

TMC6460 UART RTMI → 原有电机 UART 接收分流 → CRC 校验/静态 512 样本环 → GET_STATE option 3 → Rust 语义传输 → NativeRtmi → 原 ScopeStore/convertSignal → 遥测曲线。不再把语义反馈轮询伪装成 RTMI。

RTMI 配置经原有 worker 执行，UART.CONTROL(0x340)和 CH0～CH6(0x344～0x34A)写入后读回；CH7关闭。保留普通协议 CRC 设置，开启 RTMI CRC。原始 32 位值与 MCU 接收时间戳进入曲线；generation/boot 变化、连续3秒无样本会报告错误。前端单请求在途，读缓存不接管 UART。

依据本地 TMC6460 Rev.0 手册第37、40～44、192～194页与电机板 PCB 手册：M9 链路为 THVD1426 半双工 RS485。自动 RTMI 与主控请求必须避让；仅在观测到最后一个通道有效帧后、下一次突发前足够长的空闲窗口启动普通请求，预留事务与时序保护时间。漏帧时不推测窗口。

当前触发频率上限约100Hz，另限制总帧率≤600帧/秒，具体取决于 PWM 频率和通道数。配置/启停要求驱动禁能。485 默认上送每2次突发中的1次；CAN 默认每12次中的1次，这是主动抽取，不等于缓存溢出丢样。页面显示实际配置、抽取及丢样/错误计数，不能把期望频率当实测速率。

停止采集恢复原 RTMI CRC/采样/控制位并读回；只 W1C 确认本次捕获新增 UART 通信事件，不清 CHIP 电气故障。会话丢失由 worker 停流；存储/ROM 操作与 RTMI 互斥。

## 本轮失败与修正

1. 初次 DFU 使用4096 gap被镜像校验拒绝；当前业务必须1024(0x400)，改正后升级通过。
2. 新增 RtmiRead/CanStart 两个包装函数漏 return，导致返回值不确定、RTU头异常及CAN溢出。已补齐，并在测试中加入生产绑定严格编译，防止仅测 runtime=0 遗漏。
3. 仅按帧分流不能解决半双工碰撞，故加入实测空闲窗口门控。
4. 停流未恢复 RTMI_CRC_EN 导致再次初始化异常，现恢复原设置；UART事件残留按捕获前后差值确认。
5. 原存储 acquire 先取消事务再等待的时序仍需专门暖启动压力验证；本轮未改，不能据此宣称所有历史UART故障已解决。

## 待验收

运动中连续RTMI与实时PI、更多电机及更长时间压力、断链/物理掉电组合、页面目视效果仍需分别验收。本轮未发送使能或运动命令，不以静止波形证明运动动态正确。旧桌面EXE不会自动获得新增Rust后端；当前交付为源码与已升级的板上APP。
